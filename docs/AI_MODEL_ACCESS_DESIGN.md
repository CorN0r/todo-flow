# TodoFlow 模型接入模块设计 v1

更新日期：2026-10-25  
状态：已完成四轮设计交流，首版范围已确认，尚未实施。本文分别记录用户决定、具体设计方案和待验证的技术事项；文档交付不代表功能已经实现或通过运行验证。

## 1. 目标与已确认选择

目标：为 TodoFlow 内置 AI 功能提供可以复用的模型配置、凭证管理、调用、验证与诊断能力。具体功能通过这一模块使用模型，用户在 TodoFlow 内完成操作。

用户已确认：

- 首版由用户提供自己的 API Key，TodoFlow 直接连接其选择的模型服务。
- 首版先完成 Windows，接口设计兼顾后续 Android。
- 首版实现 OpenAI 兼容 Chat Completions 适配器，保留其他协议的扩展位置。
- 支持多组连接和模型，手动选择一个全局默认模型。
- 本阶段同时设计并交付模型配置、调用测试与真实的任务拆解功能。
- 首版只连接云端模型，本地模型服务留待后续。
- 拆解结果先预览，允许编辑和勾选，确认后添加；保留已有子任务。
- 长期保留简要调用信息与已采纳的子任务，原始输入输出不长期保存。
- 配置界面提供常用云服务预设与自定义兼容服务入口。
- 每条拆解建议包含子任务标题和具体执行说明，不包含预计耗时。
- 信息模糊时先按现有信息拆解，并明确展示需要确认的假设。

首版不包含 TodoFlow 统一模型额度、独立云端代理、Responses 或厂商原生接口、本地模型运行管理、自动模型路由、完整对话历史和自主 Agent 执行。

下面的界面细节、参数默认值、数据契约和技术落点是基于这些选择形成的设计方案，用户未逐项确认的工程细节不应写成历史决定。

## 3. 模块边界

模型接入模块负责：

1. 管理模型服务连接、模型标识和当前选择。
2. 保存、替换、删除凭证，并提供“是否已配置”的状态。
3. 将统一请求转换为已支持的服务协议，规范化返回结果。
4. 管理请求生命周期，包括取消、超时、失败与用量信息。
5. 验证具体配置的调用能力，记录有限且可解释的诊断信息。

具体 AI 业务功能负责：

1. 根据功能与用户选择，读取必要的任务、附件及进度。
2. 组织业务提示和期望的结果结构。
3. 校验结果是否适合当前任务，并提供业务界面。
4. 经相应业务流程采纳结果，调用现有任务操作。

模型接入模块不自行扫描全部任务，也不根据模型生成的文本直接修改任务数据库。

## 4. 内部职责建议

以下名称表示职责，尚未冻结为具体代码接口。

| 组件 | 职责 |
| --- | --- |
| ConnectionConfig | 连接与模型的非敏感配置、当前选择、配置版本 |
| CredentialStore | 凭证写入、替换、删除与存在性查询；前端不通过通用配置接口读回已保存的 Key |
| ModelGateway | 接收统一请求，管理请求状态、取消、超时及统一结果 |
| ProviderAdapter | 处理具体协议的 URL、鉴权、参数与响应转换 |
| ConnectionProbe | 使用不含用户任务的测试输入验证配置，记录测试对象与结果 |
| InvocationDiagnostics | 记录错误分类、时间、耗时及服务实际返回的用量；排除凭证和完整任务正文 |

由原生后端管理网络请求与凭证；前端通过明确的服务接口使用这些能力。Windows 和 Android 复用业务契约，凭证与平台网络行为分别适配。前端不直接调用模型厂商接口；本模块也不通过调用自己的 MCP 服务器来执行内部任务操作。

## 5. 配置与凭证建议

将服务连接、模型和默认选择分开管理。同一服务连接可以挂多个模型，共用其地址和凭证。

- 服务连接：显示名称、接口类型、API 基础地址、鉴权方式、凭证引用。
- 模型条目：所属连接、服务端模型标识、显示名称、已验证的能力信息。
- 调用选择：一个设备上的全局默认模型；首版所有 AI 功能共用，不按功能分别路由。

基本原则：

- 普通配置只保存凭证引用，不保存 Key 本体。
- 凭证缺失、已配置和测试失败是不同状态。
- 凭证持久化失败时不能显示为保存成功。
- 修改地址、模型、凭证或影响请求的参数后，既有测试结论需要标记为已过期。
- 首版云端连接使用 HTTPS 基础地址和 Bearer API Key，Key 为必填项；不提供无 Key 本地服务配置。
- 支持获取模型列表，也始终允许手动填写模型标识。列表获取失败，不清空已有模型，不据此认定生成接口不可用。
- 连接、模型、默认选择、验证状态和凭证均按设备管理，不加入任务同步白名单。
- 整库备份可以包含非敏感配置与凭证引用，不包含凭证本体。现有任务数据库导入不覆盖本机模型配置，不扩展为 AI 配置迁移功能。
- 配置引用到凭证不表示本机必然持有凭证，实际查询不到时显示“需要重新填写 Key”。

Windows 凭证存储拟采用系统凭证存储，由独立接口封装；具体依赖与可用性在实现前验证。后续 Android 用相同接口适配本机存储，不把 Windows 实现直接搬到 Android。

凭证与数据库不能共用一个原子事务。保存时采用“写入新的凭证引用、提交配置、清理旧引用”的次序，失败时回滚或补偿，不把部分成功显示为保存完成。修改连接的目标来源后重新填写凭证，不自动把旧 Key 带到另一个服务。

## 6. 调用生命周期建议

每次调用固定一份请求快照：连接、模型、配置版本、必要的能力要求与输入内容。调用过程中改变全局默认模型，不改变已经发出的请求。

建议状态包括：等待执行、正在执行、已成功、已失败、正在取消、已取消。请求通过唯一标识关联发起它的界面，避免多窗口和连续操作之间串用结果。

取消表示软件停止等待、接收或处理该请求；不能承诺远端已完成的处理或费用会被撤回。

结果应区分正常完成、内容截断、拒绝处理和协议异常。中断或截断的结构化输出不能作为完整业务结果写入。

本稿建议的运行默认值：单次总超时 120 秒，允许在高级设置调整；同一任务同时只运行一次拆解；用户请求与测试共用至多两个并发槽位。首版不自动重试、不自动切换服务；失败后用户可手动重试。

可选参数按连接适配结果发送，不默认强塞 `temperature`、推理参数或不支持的输出限制字段。输出上限字段存在兼容差异，需由适配规则处理；本地同时限制输入与响应体大小，避免无界请求。具体长度和字节限制在实现时固化并记录。

网络请求期间不持有数据库锁。原生后端通过与请求绑定的进度通道返回状态和文本片段，不把正文广播到其他桌面窗口。取消后到达的晚响应不能重新覆盖界面或触发任务写入。

采纳业务结果需要独立的重复操作保护，不能把模型请求重试等同于再次执行任务写入。

## 7. 能力验证建议

将三个层次分开显示：

1. 配置已保存：配置和所需凭证已按预期保存。
2. 基础调用通过：该配置成功完成过一次真实文本生成。
3. 某功能验证通过：返回结果通过该功能要求的本地校验。

首版分别验证基础文本生成、流式接收和任务拆解样例结构。工具调用不属于首版。

能力状态至少区分“未知、样例通过、不支持、验证失败、验证已过期”。配置的验证指纹包含协议、规范化地址、模型标识、影响请求的参数与凭证版本；修改显示名称不使验证过期。

任务拆解功能始终进行本地结构校验。服务明确支持时可使用对应的 JSON 输出选项；不支持时可以通过文本生成 JSON，再按同一结构校验。一次样例输出合法 JSON，只能证明该样例通过，不能据此宣称服务提供严格 JSON Schema 保证。

验证结果仅说明某个配置与测试场景曾成功，不表示服务未来始终可用，也不表示模型所有回答都正确。连接、模型或凭证发生变化后，不沿用之前的成功标记。

## 8. 兼容接口调研

核对日期：2026-10-25。以下是官方文档声明，不是 TodoFlow 的实际兼容性测试结果。

- [DeepSeek 官方文档](https://api-docs.deepseek.com/)提供 OpenAI 兼容格式的接入示例。
- [Gemini 官方兼容文档](https://ai.google.dev/gemini-api/docs/openai)提供 Chat Completions 兼容入口，并说明部分能力有专用参数。
- [Claude 官方兼容文档](https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk)说明兼容层的部分参数存在限制，例如 `response_format` 和工具调用的 `strict`。
- [OpenAI 官方迁移文档](https://developers.openai.com/api/docs/guides/migrate-to-responses)说明 Chat Completions 与 Responses 的请求及返回结构不同，Chat Completions 仍受支持。

设计推论：可以用 Chat Completions 兼容接口覆盖首版的一组文本功能；内部接口应与该协议解耦，不能把“兼容接口”当成所有服务能力相同的保证。

## 9. 配置界面与模型测试

入口为“设置 → AI 模型”，独立于现有任务视图。页面包含服务连接列表、模型列表、全局默认模型和最近调用状态。

### 9.1 新增服务

1. 选择服务预设或“自定义兼容服务”。
2. 填写显示名称、API 基础地址和 Key；预设只预填地址与接口选项，允许用户检查。
3. 获取模型列表或手动填写模型标识，可以为同一服务添加多个模型。
4. 保存配置，再选择某个模型执行验证。保存和验证分别显示状态。
5. 用户手动选择全局默认模型；首个模型也不在后台自动改变既有选择。

首批预设拟包含 OpenAI、DeepSeek 和 Gemini，以及自定义兼容服务。预设提供已核对的地址和必要参数，不硬编码不断变化的模型清单，也不意味着所有模型都经过 TodoFlow 测试。每个预设都需要列入真实兼容性验收；未验证的预设不能标记为已验证。

API 地址明确表示基础地址，适配器在其路径后加入 `chat/completions`。不能统一强加 `/v1`，也不能因为路径以 `/` 开头而丢掉用户填写的基础路径。误填完整 `chat/completions` 地址时提示修正，避免重复拼接。

已保存的 Key 仅显示“已配置”状态，提供替换和删除操作。高级区收起超时及已支持的输出限制等选项；普通用户完成必填项即可使用。

### 9.2 验证与默认模型

- “验证连接”使用固定、短小、不含任务内容的文本输入，针对具体模型发起实际生成。
- “验证任务拆解”使用内置虚构任务，按业务结果结构校验；显示服务返回用量（如果存在）和耗时。
- 流式探测失败时可单独使用非流式请求验证；界面分别显示状态，不能偷偷改成非流式后仍声称流式通过。
- 正式功能使用已经验证可行的接收方式。未知状态需要完成一次明确的验证；验证失败不删除用户配置。
- 删除或停用默认模型前，要求选择替代模型或明确清空默认选择。模型临时不可用时显示原因，不切换到另一个服务。
- 每次验证绑定配置指纹和时间。调用失败可以更新最近状态，但不抹去历史测试事实。

## 10. 首个业务功能：任务拆解

### 10.1 入口与输入范围

入口位于任务详情的“AI 拆解”。首版用于未删除、未归档、未完成的顶层任务；挂起或放弃的任务需先恢复。现有子任务不再继续创建下一级，以符合当前层级规则，界面解释原因。

生成前等待当前任务的编辑保存成功；保存失败则先提示处理，不发送与界面不一致的旧内容。

传给模型的内容仅包含：当前任务标题、描述的文本内容、现有子任务标题与完成状态，以及用户可选填写的一句话补充要求。移除描述中的内嵌图片数据，不自动读取附件、不打开链接、不扫描其他任务。模型不需要接收数据库主键。

### 10.2 生成结果与预览

界面始终显示当前模型、生成状态、取消入口与正在使用的输入范围。支持流式的配置可展示生成进度；子任务卡片只在完整输出通过校验后出现，不能从未完成 JSON 片段创建任务。

模型结果由两部分组成：

- `assumptions`：需要用户确认的假设；没有额外假设时为空数组。
- `items`：候选子任务列表，每项包含 `title` 和 `instructions`。

建议默认生成 3–7 项能够开始执行的子任务；简单任务允许更少，首版最多接受 20 项。标题和说明为纯文本，不包含模型指定的任务 ID、原始 HTML、截止日期、优先级或预计耗时。具体字符串长度上限由统一业务校验定义。

假设单独展示，供用户判断。每项可以编辑标题和说明、勾选或取消，底部显示本次将添加的数量。补充要求后可以重新生成；新请求失败或被取消时，保留原有可用预览。与已有子任务或同批候选同名的项目标记提示，默认不勾选，允许用户明确选择。

候选在关闭相关界面或退出应用后不恢复；首版不提供完整输入输出历史。模型只返回候选内容，`proposalId`、候选 ID 与上下文指纹由软件生成。

### 10.3 采纳与一致性

采纳走独立业务命令，参数包含建议批次标识、任务上下文指纹、操作标识及用户选中的已编辑项目。不能在前端循环创建子任务。

后端在同一数据库事务内：

1. 检查本次操作是否已处理；重复提交相同内容时返回原有结果，不重复添加。
2. 检查父任务是否仍然有效，并比较父任务及现有子任务的相关内容指纹。不能只使用秒级 `updated_at` 作为唯一判断。
3. 如果生成后任务或子任务已变化，保留预览并提示重新生成或处理变化；不把旧建议直接落库。
4. 校验全部待添加项目，复用现有仓储规则创建，记录任务来源为 `agent`，同步操作与采纳回执一起提交。
5. 任意一项失败则整批回滚；全部成功后发送一次任务变化通知，并返回创建结果。

`instructions` 以纯文本安全转换后写入已有描述字段。其他任务属性沿用现有创建默认值，不由模型猜测设置。父任务和既有子任务不被覆盖或改状态。

同一建议批次首版只允许成功采纳一次；改变已采纳批次的内容再次提交返回明确冲突。采纳回执保存操作摘要和创建任务 ID，不保存原始提示或候选正文。回执随创建任务的数据保留，以支持超时后安全重试。

## 11. 数据与服务契约

以下为设计契约，具体文件和函数名可在实施中按项目约定调整。

| 对象 | 主要字段 | 存储 |
| --- | --- | --- |
| AiConnection | id、name、presetId、protocol、baseUrl、credentialRef、credentialVersion、revision、enabled | 本地数据库，不同步 |
| AiModel | id、connectionId、modelId、displayName、验证记录 | 本地数据库，不同步 |
| DefaultModel | modelEntryId，可为空 | 本地设置，不同步 |
| Credential | credentialRef 对应的 Key | Windows 系统凭证存储 |
| AiInvocation | requestId、用途、模型与配置版本标识、状态、耗时、错误类别、可选 usage | 本地简要记录 |
| BreakdownProposal | proposalId、上下文指纹、模型快照、假设、候选内容 | 当前操作内存，不长期保存 |
| AiApplyReceipt | proposalId、operationId、提交内容摘要、创建的任务 ID | 本地数据库，业务重复操作保护 |

连接和模型拟使用独立表；不把整个模型系统装进一个通用设置 JSON。全局默认项可以沿用现有本地设置机制，但不改变同步白名单。

外部业务组件通过以下能力使用模块：

- 配置：列出、保存、删除、停用连接和模型，读取或设置全局默认模型。
- 凭证：设置、替换、删除和存在性查询；不提供读取原始 Key 的前端接口。
- 验证：获取模型列表、文本调用验证、流式验证、任务拆解样例验证。
- 调用：提交统一生成请求、接收与请求绑定的进度、取消、获取最终结果。
- 业务：生成拆解建议、批量采纳选中项目；与通用模型调用分开。
- 诊断：读取有限调用摘要、清除调用摘要。

统一调用请求包含 `requestId`、用途、模型选择快照、消息、接收方式和取消控制，不直接暴露厂商请求体给任务组件。返回结果包含文本、规范化完成原因、实际返回的模型标识和可选用量。用量缺失记为未知，不能显示为零费用。

统一错误包含机器可读 `code`、用户可读说明和必要的脱敏诊断信息。至少区分配置缺失、凭证不可用、鉴权失败、模型不可用、连接失败、限流、超时、取消、不支持的能力、输出截断、格式不合法、上下文变化和重复采纳冲突。

## 12. 调用记录与本地数据行为

按用户决定，不长期保存请求正文、完整模型输出或完整对话。已采纳内容就是普通子任务，沿用任务的同步、备份与编辑机制。

调用摘要只保存用途、时间、模型与连接标识、状态、耗时、错误分类和服务实际返回的用量。不得保存 Authorization、Key、完整请求头或未经处理的错误响应体。

本稿建议调用摘要保留最近 30 天且最多 1000 条，提供清除入口；这是工程默认值，不是用户逐项确认的决定。删除调用摘要不删除子任务或采纳回执。连接被删除后，历史摘要仍可显示必要的模型名称快照。

模型未配置、离线或调用失败时，现有任务、习惯、日历和专注功能继续工作。跨端只同步实际采纳的普通任务；Android 尚未实现该模块时，不显示可点击但不能使用的 AI 入口。

## 13. 实现落点与实施顺序

拟在现有 domain 边界增加模型数据与 AI 服务契约，提供原生调用 adapter 和测试替身。设置界面增加 AI 模型区域，任务详情增加拆解面板。Rust 侧增加配置、凭证、协议适配、请求运行、验证和拆解业务模块，以及对应数据库迁移。

按依赖顺序实施：

1. 配置、模型条目、默认选择、凭证管理与迁移；先验证凭证存储可用。
2. Chat Completions 适配、地址处理、请求状态、取消、错误分类和有限诊断。
3. 服务预设、自定义配置、模型列表手填或获取、实际调用与能力验证。
4. 任务上下文整理、拆解结构校验、假设与候选预览。
5. 批量采纳事务、任务来源、上下文检查、重复操作回执和现有同步集成。
6. 完成 Windows 实际验收，保留 Android 的接口和适配边界。

首版不引入通用 Agent 框架、向量库或复杂工作流引擎。协议适配器保持可替换，为未来 Responses、厂商原生接口和本地模型留下扩展位置。

## 14. 验收场景与证据边界

| 场景 | 预期结果 |
| --- | --- |
| 创建多个服务与多个模型，手动选择默认模型，重启应用 | 非敏感配置与默认选择保持，凭证通过本机存储可用 |
| 凭证写入失败、配置提交失败 | 不显示保存完成，不留下可用但错误的默认引用 |
| 普通设置读取、数据库备份、任务同步 | 不包含原始 Key；模型配置不进入任务同步 |
| 模型列表接口不可用，但手填模型可以生成 | 仍能配置和验证该模型 |
| 基础地址包含版本或兼容前缀 | 正确保留基础路径，不重复或误加 `/v1` |
| Key 错误、模型不存在、限流、断网或超时 | 有明确错误分类，不自动换服务，不影响普通任务操作 |
| 生成中切换默认模型或修改连接 | 已发出的请求仍对应原快照，后续请求使用新配置 |
| 取消流式生成后出现晚响应 | 不更新为成功，不创建任务，不串入其他窗口 |
| 生成内容被截断、拒绝或结构不合法 | 不产生可采纳任务，保留明确失败信息 |
| 对含内嵌图片和附件的任务执行拆解 | 首版只发送已定义的文本上下文，不自动上传图片或读取附件 |
| 任务模糊且已有子任务 | 显示假设和新增候选，保留并考虑已有子任务 |
| 编辑与勾选候选后采纳 | 仅添加所选标题和说明，来源标记一致，不设置模型猜测的日期等字段 |
| 父任务或子任务在生成后发生变化 | 采纳前识别变化，不直接写入旧建议 |
| 同批项目一项写入失败，或同步记录失败 | 整批回滚，无半批任务和残缺回执 |
| 连续点击采纳、采纳请求超时后重试 | 返回相同创建结果，不重复添加 |
| 清理调用摘要或重新打开应用 | 不恢复完整输入输出；已采纳任务和重复操作保护不受影响 |

实现后用有意义的适配器、状态和事务测试验证失败路径，并进行 Windows 应用内真实调用验收。测试替身不能证明厂商兼容性；HTTP 成功不能证明结构化结果可用；任务生成成功也不能替代采纳与同步验收。

真实厂商验收使用测试账户或专门授权的凭证与虚构任务，未取得实际调用结果前，预设只标为文档适配，不能标为运行验证通过。

## 15. 技术验证事项

下列事项不改变已确认范围，但在实现前或最早阶段需要验证并记录结果：

- Windows 凭证存储依赖、保存与失败补偿；不采用明文回退。
- 原生网络在目标 Windows 环境下的 TLS、代理、流式与取消行为。
- 初始预设的基础地址、模型列表、参数差异与任务拆解输出适配。
- 批量采纳事务与现有同步记录的组合，确保成功、失败、重复调用语义一致。
