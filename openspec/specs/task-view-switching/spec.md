# task-view-switching Specification

## Purpose

让用户在任一任务范围（我的一天、计划、全部任务、标签）的页头选择列表、便签墙、一体式、看板或四象限视图，使“看哪一批任务”与“怎么看”相互独立。

## Requirements

### Requirement: 页头提供视图菜单

每个任务集合页面的标题区 MUST 提供视图入口，显示当前视图的名称，并能切换到列表、便签墙、一体式、看板、四象限五种视图之一。

#### Scenario: 打开视图入口
- **WHEN** 用户点击标题区的视图入口
- **THEN** 看到五种视图及当前视图的标记

#### Scenario: 选择看板
- **WHEN** 用户选择“看板”
- **THEN** 当前范围的任务以看板显示，视图入口显示“看板”

#### Scenario: 从看板回到列表
- **WHEN** 用户在视图入口中选择“列表”
- **THEN** 恢复列表显示，视图入口显示“列表”

### Requirement: 视图与范围正交

视图 MUST 作用于当前范围的任务集合。切换目的地或日期范围时视图 MUST 保持，视图选择 MUST 在应用重启后保持。

#### Scenario: 未来 7 天的看板
- **WHEN** 用户在“全部任务”选择看板后进入“计划 › 未来 7 天”
- **THEN** 看板只显示截止日期在该范围内的任务

#### Scenario: 视图跟随目的地
- **WHEN** 用户选择一体式后打开任意标签
- **THEN** 标签页面以一体式显示

#### Scenario: 重启后保持视图
- **WHEN** 用户选择看板后重启应用
- **THEN** “全部任务”仍以看板显示

### Requirement: 我的一天保留专属内容

“我的一天”在看板或四象限视图下 MUST 继续显示昨日未完成、建议和今日重点，视图 MUST 只替换其任务清单区。

#### Scenario: 我的一天下的看板
- **WHEN** 用户在“我的一天”选择看板
- **THEN** 昨日未完成、建议和今日重点仍在，下方的清单区显示看板

### Requirement: 看板的行为

看板 MUST 可按优先级、标签或完成状态分列，分组入口 MUST 位于看板视图内。拖拽卡片到另一列 MUST 修改对应的优先级、标签或完成状态，默认分组 MUST 为优先级。

#### Scenario: 拖到高优先级
- **WHEN** 用户把卡片拖到“高”列
- **THEN** 该任务的优先级变为高

#### Scenario: 拖到无标签
- **WHEN** 用户在某个标签页的看板中把卡片拖到“无标签”列
- **THEN** 该任务失去当前标签，并从看板中移除

#### Scenario: 切换分组
- **WHEN** 用户在看板中选择按标签分组
- **THEN** 列变为各个标签加“无标签”

### Requirement: 四象限的行为

四象限 MUST 按紧急性与重要性分为四个象限；拖拽卡片到另一象限 MUST 修改对应的截止日期与优先级，规则与变更前相同。

#### Scenario: 拖到重要且不紧急
- **WHEN** 用户把卡片拖到“不紧急但重要”象限
- **THEN** 该任务的优先级变为重要，截止日期按变更前的规则处理（原日期保留或被清除）

### Requirement: 看板与四象限只显示可分组的根任务

看板与四象限 MUST 只显示当前范围的根任务，不把子任务单独列为卡片。四象限 MUST NOT 包含已完成或已放弃的任务。拖拽使任务不再属于当前范围时，该任务 MUST 从当前视图中移除。

#### Scenario: 子任务不占卡片
- **WHEN** 当前范围的某个根任务带有子任务
- **THEN** 看板与四象限中只有该根任务一张卡片

#### Scenario: 四象限不含已完成
- **WHEN** 当前范围包含已完成或已放弃的任务
- **THEN** 它们不出现在任何象限

#### Scenario: 拖拽后离开范围
- **WHEN** 用户在“计划 › 明天”的四象限中把卡片拖到会使截止日期被清除的象限
- **THEN** 该任务从当前象限视图中移除

### Requirement: 状态筛选适用于全部视图

状态筛选 MUST 同样约束看板与四象限显示的任务：看板 MUST 显示与列表相同的匹配根任务，四象限 MUST 显示其中未完成且未放弃的任务。筛选与视图入口 MUST 同时可见。

#### Scenario: 未完成筛选下的看板
- **WHEN** 用户选择“未完成”后切换到看板
- **THEN** 各列只包含未完成的根任务

### Requirement: 看板与四象限下不提供的操作

看板与四象限视图下 MUST NOT 提供展开 / 收起子任务与多选入口；进入这两种视图时若处于多选状态 MUST 退出多选。从一体式切换到其他视图时 MUST 清除一体式中的任务选中。

#### Scenario: 不显示多选
- **WHEN** 用户切换到看板
- **THEN** 标题区不显示“多选”和展开子任务的入口

#### Scenario: 退出多选
- **WHEN** 用户在列表中开启多选后切换到四象限
- **THEN** 多选状态退出，没有任务保持勾选

#### Scenario: 离开一体式
- **WHEN** 用户在一体式中选中一个任务后切换到列表
- **THEN** 没有任务保持选中，侧边详情面板不打开

### Requirement: 排序适用于全部视图

看板各列与四象限各象限内的任务顺序 MUST 遵循标题区的排序设置，看板与四象限 MUST NOT 另设独立的排序入口。

#### Scenario: 列内顺序
- **WHEN** 用户把排序改为“截止日期 (近→远)”
- **THEN** 看板每一列内的任务按截止日期由近到远排列

### Requirement: 旧独立页面路由

导航到旧四象限或旧看板页面的地址时 MUST 显示“全部任务”并启用对应视图，MUST NOT 显示空白。

#### Scenario: 导航到旧看板地址
- **WHEN** 应用内导航到旧看板页面的地址
- **THEN** 显示“全部任务”的看板视图，侧边栏“全部任务”为选中态
