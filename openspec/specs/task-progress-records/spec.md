# task-progress-records Specification

## Purpose

为 TodoFlow 任务与子任务提供完全自愿、可编辑和可删除的进展记录，同时保留本机真实状态转换作为回顾事实，使用户能够跨天接续工作，并在资料不完整时明确区分已知进展、当前状态和未知历史。

## Requirements

### Requirement: 自愿使用与既有操作独立

系统 MUST 通过用户主动进入的轻量入口提供记录，MUST NOT 在完成任务、结束或暂停专注、切换任务、关闭详情时插入填写、确认放弃或必填步骤。系统 MUST NOT 默认发送记录提醒、展示待补记录、连续记录指标或因未记录降低任何任务功能。配置模型、打开页面和完成任务 MUST NOT 自动调用 AI。

#### Scenario: 始终不使用记录
- **WHEN** 用户从未进入进展记录页签并连续创建、完成任务及使用专注
- **THEN** 原操作可直接完成，不出现记录表单、提醒或必须处理的空状态

#### Scenario: 关闭带草稿的详情
- **WHEN** 用户已有未保存记录并切换任务或关闭详情
- **THEN** 操作直接执行，草稿留在本次应用会话，不自动提交、不要求先填写或放弃

### Requirement: 单文本记录与主动保存

系统 MUST 允许以单一纯文本正文记录，去除首尾空白后长度为 1–2000 个 Unicode 字符；类型、百分比、卡点和下一步 MUST NOT 为必填字段。Enter MUST 换行，按钮或 Ctrl+Enter MUST 主动保存。记录日期 MUST 默认今天，并允许选择过去日期补记；未来日期 MUST 被拒绝，创建／修改时间 MUST 与补记日期区分。

#### Scenario: 写一句进展
- **WHEN** 用户输入“初稿完成，正在等待成本数据”并保存
- **THEN** 生成一条独立记录，不要求补充其他字段，不替换任务描述或改变任务状态

#### Scenario: 空白或未来日期
- **WHEN** 用户提交空白正文、超长正文或未来日期
- **THEN** 系统显示具体原因，保留可修改输入，不保存记录

#### Scenario: 补记过去进展
- **WHEN** 用户今天主动把记录日期选择为昨天并保存
- **THEN** 记录参加昨天的进展回顾，界面仍能辨识今天创建，不伪造昨天的任务状态事件

### Requirement: 编辑删除与草稿一致性

系统 MUST 支持编辑、删除已保存记录，并在当前会话按任务保留草稿。切换页签、任务或暂时关闭详情 MUST 保留输入；进程退出后的未保存草稿不承诺恢复，保存语义 MUST 在输入区可知。保存失败 MUST 保留正文供重试；同一保存操作重试 MUST NOT 新增重复记录。并发编辑 MUST 检查记录版本，冲突保留当前输入，旧响应 MUST NOT 覆盖新编辑或恢复已删除正文。

#### Scenario: 写入失败后重试
- **WHEN** 保存记录失败，用户修复问题后重试同一操作
- **THEN** 输入保留，最终只出现一条记录，任务正文与更新时间不被额外改写

#### Scenario: 两处编辑同一记录
- **WHEN** 某份编辑提交前记录已由另一处修改
- **THEN** 系统明确提示内容已变化并保留本地输入，不自动覆盖新版本

#### Scenario: 删除后旧保存响应返回
- **WHEN** 用户删除记录后旧请求的保存响应到达
- **THEN** 时间线仍显示实际删除状态，不恢复正文或创建第二条记录

### Requirement: 任务归属与父子聚合

系统 MUST 将一条记录归属于一个确定任务，支持顶层任务和已有子任务。根任务默认只展示自身记录，MUST 提供显式的“含子任务”选择，并标识每条聚合记录的来源。详情聚合 MUST 按当前父子关系，周期回顾 MUST 按来源保存时的根任务归类；任务移动不能复制记录或改写已存历史归属。同一记录在聚合与回顾中 MUST 只计一次；子任务记录或完成 MUST NOT 推断父任务完成。记录 MUST 独立于“我的一天”的每日刷新而保存。

#### Scenario: 根任务查看子任务进展
- **WHEN** 用户在根任务中开启“含子任务”
- **THEN** 展示符合范围的子任务记录及来源标记，每条只出现一次

#### Scenario: 新一天继续工作
- **WHEN** 本地日期变化且任务未被加入新的“我的一天”
- **THEN** 历史记录仍可从任务进入，任务不被自动加入今日，也不自动调用模型

#### Scenario: 子任务移动后查看
- **WHEN** 带记录的子任务移动到另一个根任务
- **THEN** 新根任务可按当前关系聚合其记录，旧周期回顾仍按记录保存时归属解释，不创建或重复统计记录

### Requirement: 真实状态事件

系统 MUST 提供可关闭的本机状态历史留存，候选首版默认开启。开启期间 MUST 自动记录本机真实发生的完成、重新打开、挂起、恢复进行、放弃、恢复使用等状态转换，记录可确认的发生时间与来源。关闭 MUST 不影响任务操作或手写记录，不删除已有历史；重新开启 MUST 标记关闭区间的资料缺口，不补猜事件。

相同状态重复写入、查看、普通字段编辑和迁移 MUST NOT 产生执行事件。留存开启时对应事件与任务转换 MUST 同一事务提交或回滚，并覆盖所有本机任务写入口，不能仅覆盖某个界面按钮。事件 MUST NOT 复制任务描述、附件或手写记录正文。

#### Scenario: MCP 完成任务
- **WHEN** 本机 MCP／CLI 将未完成任务变为完成
- **THEN** 保存一条真实完成事件，之后重复写入已完成状态不新增完成事件

#### Scenario: 修改已完成任务标题
- **WHEN** 用户修改已完成任务的标题或标签
- **THEN** 不生成新的完成事件，真实完成日期不随更新时间改变

#### Scenario: 事件写入失败
- **WHEN** 历史留存开启且一次真实状态转换对应的事件无法写入
- **THEN** 任务变化与事件共同回滚，不留下已完成却无对应新事件的半次操作

#### Scenario: 关闭后重新开启
- **WHEN** 用户关闭状态历史留存，继续操作任务，稍后重新开启
- **THEN** 任务操作照常完成，手写记录仍可使用，关闭区间明确为资料缺口，不回填猜测的状态转换

### Requirement: 历史覆盖与外部状态边界

系统 MUST 记录并展示本机事实的历史覆盖起点及清理／导入缺口，MUST NOT 用任务更新时间、迁移时间或同步接收时间反填未知完成时间。只收到其他设备的当前状态时，MUST 将真实发生时间标为未知；此状态可以作为当前参考，但 MUST NOT 进入确定日期的完成计数。恢复真实事件 MUST 保留原 ID、时间和来源。

#### Scenario: 升级时已有完成任务
- **WHEN** 用户升级后查看升级前的回顾周期
- **THEN** 显示历史资料不完整，不把旧已完成任务算作升级当天完成，也不显示为完整的零活动

#### Scenario: 收到 Android 完成快照
- **WHEN** 本机只同步收到另一设备的已完成状态而无真实事件
- **THEN** 可显示当前已完成但时间未知，不将接收时刻认作实际完成时刻，回顾说明跨端资料缺口

### Requirement: 本机保存与可恢复的数据生命周期

首版记录、事件及覆盖信息 MUST 持久保存在本机，不新增同步实体；Android MUST NOT 出现可点击但无法执行的新入口。已保存记录和事实 MUST 长期保留至主动删除或清理，不随 AI 调用摘要、每日重点或跨日刷新清理。删除记录或任务关联的手写正文 MUST 清除正文；最小去重标记可保留。任务删除后最小历史状态事实可保留，来源 MUST 标记不可打开；主动清理事实后 MUST 标记覆盖缺口。

备份 MUST 包含新业务数据及来源关系；现有任务导入 MUST 默认不改动本机记录。用户显式选择同时恢复进展与回顾时，MUST 校验版本和引用、原子恢复、跳过内容一致的同 ID 数据，并拒绝不同内容的同 ID 覆盖；旧备份缺少新数据 MUST 可兼容。恢复 MUST NOT 改写本机模型配置或伪造今日活动。

#### Scenario: 清理 AI 调用摘要
- **WHEN** 用户清理模型调用摘要或每日 AI 卡片到期
- **THEN** 已保存进展和事实历史仍存在，未保存模型输出不会被恢复

#### Scenario: 备份后恢复
- **WHEN** 用户从含进展资料的备份显式恢复这些数据
- **THEN** 记录和来源一致恢复，事件保持原时间，重复恢复不重复计数，本机模型选择不被覆盖

#### Scenario: 恢复冲突或历史清理
- **WHEN** 恢复遇到相同 ID 不同内容，或用户主动清理某段事实历史
- **THEN** 恢复冲突不产生部分覆盖；主动清理后的该时段标为部分资料可用，不误报为无活动
