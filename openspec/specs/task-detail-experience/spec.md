# task-detail-experience Specification

## Purpose

为 TodoFlow 任务详情建立适合持续扩展的信息层级，使内容编辑、子任务执行与自愿进展记录各有清晰空间，同时在侧栏和一体式详情中维持可访问、一致且不丢失编辑的使用体验。

## Requirements

### Requirement: 默认内容与主动进展页签

Windows 详情 MUST 提供“任务内容／进展记录”两个页签，普通选中一个任务时 MUST 默认内容页，记录不得自动展开或获得输入焦点。标题、完成状态和核心属性摘要 MUST 在两个页签保持可辨识；回顾入口 MUST 位于独立页面，不继续增加详情内长表单。

#### Scenario: 打开未使用记录的任务
- **WHEN** 用户选择任意任务查看详情
- **THEN** 默认看到内容和原有任务操作，进展记录仅作为轻量可发现入口，不显示要求填写的空面板

#### Scenario: 主动查看历史
- **WHEN** 用户切到进展页签
- **THEN** 在同一详情空间查看该任务记录，仍能辨识当前任务标题和状态

### Requirement: 属性与操作分层

系统 MUST 在公共头部保留标题、完成操作、关键属性摘要与常用操作，使用明确的“更多属性／更多操作”容纳其余原有功能。日期、优先级、标签、提醒、重复、置顶、桌面固定、删除等既有能力 MUST 仍可到达；已设置的提醒或重复 MUST 有可辨识摘要。系统 MUST 支持长标题、多标签和窄宽度，不能以悬停作为唯一入口。

#### Scenario: 已有提醒与重复
- **WHEN** 任务存在提醒或重复设置
- **THEN** 收起更多属性时仍有摘要提示，展开后可以查看和修改原设置

#### Scenario: 窄详情与键盘访问
- **WHEN** 用户在 400px 侧栏或较窄一体式详情中使用键盘
- **THEN** 主要操作和页签可聚焦、具有明确名称和选中状态，不发生横向溢出或依赖悬停才能找到操作

### Requirement: 内容编辑与请求接续

内容页 MUST 保留描述的富文本能力、子任务说明与其既有保存契约，以及就近的 AI 润色／拆解入口。长描述 MUST 可展开和编辑，空描述 MUST NOT 强占大块空间。页签切换 MUST 保留本次编辑、记录草稿、滚动位置和 AI 会话，MUST NOT 自动发起新请求。任务切换后数据与晚响应 MUST 按任务隔离，防止内容串入其他任务。

#### Scenario: 编辑时切换页签
- **WHEN** 用户编辑描述或记录后切换页签再返回
- **THEN** 当前编辑与滚动位置可接续，记录不因失焦而被自动发布为进展，既有描述保存规则继续生效

#### Scenario: AI 生成中切换
- **WHEN** 润色或拆解生成中用户切到记录再返回
- **THEN** 显示同一请求进度或结果，不重复调用、不丢失预览、不因切换自动采纳

### Requirement: 容器一致性与真实时间显示

侧栏详情和一体式详情 MUST 使用相同的信息顺序、页签语义和状态管理，正文 MUST 避免嵌套的多个主要滚动区。详情显示“完成于”时 MUST 使用可确认的完成事件，MUST NOT 用通用更新时间代替；没有可靠事件时 MUST 说明“完成时间未记录”。

#### Scenario: 切换任务视图
- **WHEN** 用户通过侧栏或一体式详情查看同一任务
- **THEN** 两处记录、内容与操作一致，不出现某个容器特有的丢稿或不可达功能

#### Scenario: 完成后继续编辑
- **WHEN** 已完成任务的描述被再次修改
- **THEN** 显示的真实完成时间不变；旧任务缺少真实事件时显示未知，不把本次编辑时间标为完成时间
