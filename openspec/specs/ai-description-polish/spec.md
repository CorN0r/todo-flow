# ai-description-polish Specification

## Purpose

为任务详情提供 AI 描述生成/润色:基于默认模型把空缺或杂乱的任务描述改写为清晰可执行的纯文本说明,预览编辑后经现有任务更新流程写入。

## Requirements

### Requirement: 入口与输入范围

"AI 润色"入口位于任务详情描述区,未完成任务可用;生成前 MUST 等待当前编辑保存完成(与拆解一致的 flush 语义)。传给模型的内容 MUST 仅包含任务标题、描述转换后的文本、现有子任务标题与完成状态、以及可选的用户润色方向;MUST NOT 包含内嵌图片数据、附件、链接内容或数据库主键。

润色方向为可选补充输入,长度 MUST 不超过 200 字符,超限 MUST 拒绝并提示;它随生成请求发送并在提示词中优先遵循(以不丢失原有信息为前提),会话内 MUST 保留供重新生成复用与继续编辑。

#### Scenario: 描述未保存时发起润色
- **WHEN** 描述刚被编辑仍在防抖待保存状态时点击"AI 润色"
- **THEN** 系统先完成保存;保存失败则提示并停止,不发送旧内容

#### Scenario: 含图片描述
- **WHEN** 描述含内嵌图片时生成
- **THEN** 模型只收到剥离图片后的文本

#### Scenario: 附带润色方向
- **WHEN** 用户在方向输入框填写"更正式,突出数据"后发起生成
- **THEN** 该方向随请求发送,模型输出在不丢失原有信息的前提下优先遵循;重新生成沿用输入框当前内容

#### Scenario: 方向超限
- **WHEN** 方向超过 200 字符时发起生成
- **THEN** 请求被拒绝并提示"润色方向过长",不调用模型

### Requirement: 输出与本地校验

输出 MUST 为纯文本(允许换行分段),长度 1..=4000 字符;系统 MUST 在本地校验长度与非空,完成原因为截断或校验失败时 MUST NOT 产出可采纳预览。同一任务同时只允许一个 AI 生成(与任务拆解共用单飞约束),重复发起返回可读提示。

#### Scenario: 输出被截断
- **WHEN** 生成被截断(finish_reason != stop)
- **THEN** 显示明确失败信息,不产出预览

#### Scenario: 生成中重复发起
- **WHEN** 同一任务润色进行中再次点击
- **THEN** 返回"正在处理中"类提示,不并发第二个请求

### Requirement: 预览与采纳

预览 MUST 显示当前模型、状态、取消入口,内容可编辑。采纳 MUST 走现有任务更新流程仅替换描述字段(纯文本按既有换行包装规则转为存储格式),MUST NOT 修改其他字段或任务来源标记;采纳后预览关闭。取消或失败时 MUST NOT 改动描述。调用摘要记录 purpose=polish 的用途、状态与用量。

#### Scenario: 编辑后采纳
- **WHEN** 用户在预览中修改文本后采纳
- **THEN** 描述字段被替换为编辑后的内容,其他字段不变

#### Scenario: 取消生成
- **WHEN** 用户在生成中取消
- **THEN** 描述保持原样,晚到的响应不落地
