## Why

TodoFlow 的任务状态已经包含完成、挂起和放弃，但主要任务页面的筛选入口不一致：桌面端只有部分页面能按完成状态筛选，移动端也无法只查看挂起任务。用户因此难以隐藏已完成内容、聚焦当前可执行任务，或集中处理暂时搁置的任务。

## What Changes

- 建立统一的任务状态筛选语义，提供全部、进行中、已完成、挂起、已放弃和超期视图。
- 在桌面端的全部任务、日期范围、今天、我的一天和标签页面复用同一套筛选控件、计数与空状态。
- 在移动端任务页扩展现有筛选芯片，支持挂起和已放弃任务，并保持适合触控与窄屏的布局。
- 让状态筛选与搜索、标签、排序、列表/便签墙/一体式视图以及批量选择正确组合。
- 为筛选判定提供共享的纯函数和明确的状态优先级，避免不同页面各自实现后产生语义偏差。
- 筛选仅影响当前可见集合，不修改任务数据；用户切换页面或重新进入任务页时使用产品定义的默认状态。

## Capabilities

### New Capabilities

- `task-status-filtering`: 定义跨桌面端与移动端的任务状态视图、筛选交互、组合规则、计数、空状态和可访问性行为。

### Modified Capabilities

无。

## Impact

- 前端共享层：`PageTitle` 附近的状态筛选控件、任务状态判定工具、国际化文案与 UI 状态。
- 桌面端页面：`TodayPage`、`DateFilterPage`、`MyDayPage`、`TagPage`，以及它们向 `TaskList`、`StickyWall`、`UnifiedLayout` 传递的可见任务集合。
- 移动端：`MobileTasksPage` 的状态芯片、组合筛选与空状态。
- 测试：共享筛选逻辑、桌面页面行为、移动端组合筛选、计数及批量选择范围。
- 数据与接口：沿用现有 `Task` 状态字段和任务仓储能力，不需要数据库迁移、新依赖或破坏性 API 变更。
