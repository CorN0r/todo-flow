## Context

动机见 `proposal.md`。与方案直接相关的现状和约束：

- **侧边栏**（`src/components/layout/Sidebar.tsx`）：主导航 7 项与“计划中”4 项共用同一组样式（14px、34px 高、同色）。分组标题用全局 `.section-label`（11px、`uppercase`、`letter-spacing: 1px`，是为英文大写设计的），这个类在设置页、任务详情等 15 处也在用。“计划中”可折叠，标签不可。折叠成图标栏时只有 8 个图标，没有标签入口。
- **路由**：`/` 是“今天”页面（按截止日期为今天过滤）；`/myday` 是“我的一天”；`/date/:filter`（`all`、`today`、`tomorrow`、`this-week`、`this-month`）由同一个 `DateFilterPage` 承担，标题取自配置表；`/matrix`、`/kanban` 是各自取全量根任务的独立页面，各带一套页头和 5 项的简化排序。桌面主窗口的启动落点是 `/date/all`（`src/platform/appSurface.ts`）。
- **视图**：`uiStore.taskViewMode` 取 `list | wall | unified`，全局且持久化在 localStorage。“list / wall / unified”的三目渲染和容器高度分支在四个页面各写一遍；页头是一个循环按钮（`PageTitle.onToggleViewMode`）；`TaskDetailPanel` 用 `taskViewMode !== 'unified'` 决定是否打开；离开一体式时清除选中任务的逻辑也是四个页面各写一遍。
- **状态筛选**：各页面用 `useDesktopTaskStatusFilter(topLevel)` 得到 `filteredTasks`（带子任务的根任务）。`task-status-filtering` 规格要求各视图使用同一个可见集合。
- **会受影响的调用方**：`ReviewPage` 的返回和“从回顾打开任务”都导航到 `/`；`CommandPalette` 的导航命令只有今天、日历、设置。`DashboardPage` 跳 `/date/all` 并带状态筛选、`SearchBar` 跳 `/tag/:id`，两者不受影响。
- **主题**：六套主题。颜色靠 `index.css` 里按 Tailwind 类名覆盖（例如 `.warm .dark\:text-\[\#C4C4CC\]`），新引入的色值类要在 warm、lumina 的覆盖表里补行，否则会跳出这两套主题的色相。玻璃主题下侧边栏带 `backdrop-filter`，是独立的层叠上下文，浮层必须 Portal 加固定定位。
- **项目约定**（`CLAUDE.md`）：用显式 hex 颜色；不做过早抽象；滚动区用 `h-full flex flex-col` 加 `flex-1 min-h-0`，不写 `calc(100vh - Npx)`；界面文案为简体中文；前端改动必须在 `npx tauri dev` 下验证。

## Goals / Non-Goals

**Goals:**

- 地址只表达“看哪一批任务”，视图只是一份全局状态——范围与视图正交，并且不产生组合爆炸。
- 视图渲染只有一处开关，以后再加视图只改一个组件。
- 每个阶段都能单独发布和回退；全部是前端改动，不迁移数据。
- 日期范围、状态筛选、拖拽改属性的结果口径一律不变。

**Non-Goals:**

- 不按范围分别记忆视图，也不把视图写进地址。
- 不把“日历”并入视图体系（它有自己的月 / 周 / 天）。
- 不重做折叠成图标栏时的结构，也不在这个形态下提供标签入口。
- 不提供“把某个视图固定到侧边栏”的个性化设置。
- 不调整 `.section-label` 在其他页面的表现。

## Decisions

### D1 路由表达范围，视图是一份全局持久状态

- 把 `uiStore.taskViewMode` 扩展为 `list | wall | unified | kanban | matrix`，仍然是全局、仍然持久化。页面只决定取哪批任务，用哪种视图呈现由这份状态决定。
- 读取 localStorage 时校验取值，不在集合内就回落到 `list`。类型 `TaskViewMode` 在 `uiStore` 定义一处，`PageTitle` 改为引用（现在两处各写了一遍字面量联合）。

备选：每个范围各自记忆视图。更贴近“每个地方有自己喜欢的样子”，但会改变列表 / 便签墙 / 一体式现有的跨页面保持行为，还多出一份按范围键控的状态。否决。

备选：看板与四象限是临时“镜头”，切换目的地后自动回到原来的版式。实现最简单，但习惯用看板的人每换一个范围都要重新选一次，而这两个视图原本是侧边栏一次点击可达的。否决。

### D2 视图渲染收口到一个组件

- 从两个独立页面里抽出 `KanbanBoard`、`MatrixBoard`（放 `src/components/tasks/`），只接收一个参数：当前范围经状态筛选后的根任务，也就是各页面已有的 `filteredTasks`。列与象限的定义、拖拽、卡片原样搬过去。
- 传给这两个组件的任务要去掉 `children`。`TaskCard` 会读取 `task.children`，原来的独立页面取数时不带子任务；不去掉的话四象限里的卡片行为会变。
- 新增 `TaskViewBody`，负责“视图 → 组件”的映射和容器高度语义：`unified`、`kanban`、`matrix` 需要确定高度（`flex flex-col overflow-hidden`），`list`、`wall` 随页面滚动。`MyDayPage`、`DateFilterPage`、`TagPage` 三处改为调用它。
- 这与“不做过早抽象”的约定不冲突：同一段三目已经在四个页面各有一份，再加两种视图就是三处乘五个分支，而且高度语义必须完全一致。
- 排序统一走页头的排序（`sortTasks(tasks, sortMode)`），两个独立页面各自的简化排序列表删除。看板的“分组”（优先级 / 标签 / 完成）改成看板顶部的一行紧凑分段控件，不放进页头：页头已有标题、状态筛选、排序、多选、新建，再加一组三段控件会撞上 `task-status-filtering` 的“标题栏不重叠”场景。
- 四象限沿用“只放未完成且未放弃的任务”的规则，叠加在状态筛选之上。所以状态筛选是“全部”时，四象限是列表的子集，其余四种视图与列表相同。

### D3 页头视图菜单，切换视图的副作用收进 store

- `PageTitle` 的 `onToggleViewMode` 换成 `onViewChange(mode)`。按钮显示当前视图的图标和名称，外加下拉箭头；下拉沿用同文件里排序下拉的做法（Portal 加固定定位），每一项都标出当前视图。
- 看板与四象限下不渲染“展开子任务”和“多选”。
- 副作用集中到 `setTaskViewMode`：离开 `unified` 时清除 `selectedTaskId`（原先四个页面各写一遍）；切到 `kanban`、`matrix` 时退出多选。

备选：保留循环按钮，从三种循环到五种。到四象限要点四下，而且按钮只显示图标。否决。

备选：页头放五个并排的分段按钮。比下拉少点一次，但在较窄的窗口里会和状态筛选抢宽度。否决。

### D4 “计划”复用 `/date/:filter`，范围切换在页面内导航

- `filterConfig` 的键不动。导出“计划范围”集合 `today`、`tomorrow`、`this-week`、`this-month`；`all` 不在其中。
- `DateFilterPage`：`all` 保持标题“全部任务”、没有范围切换。计划范围的标题统一为“计划”，标题行下方放一行范围分段控件，点击即导航到 `/date/<范围>`。“未来 7 天”原有的日期条保留，仍然只用于展示。各范围自己的页头图标取消，统一用“计划”的图标。
- 侧边栏“计划”的目标：当前就在某个计划范围时用当前地址（保证选中态正确），否则是 `/date/<上次查看的范围>`。上次查看的范围放在 `uiStore`，只存内存，默认 `this-week`，由 `DateFilterPage` 在计划范围下更新。
- “今天”范围保留在计划里：`/date/today` 本来就在配置表中，独立的今天页面去掉之后，它是按截止日期看今天的唯一入口。

备选：新路由 `/planned`，范围作为页面状态。要改所有 `/date/...` 的调用和测试，范围也不再体现在地址里。否决。

名称用“计划”：它是现有分组名“计划中”的自然延续，也和 Microsoft To Do 的 Planned 中文译名一致。页头同时有标题“计划”和范围控件，足以说明这里的“今天”是按截止日期的时间线，不是“我的一天”。

### D5 单一的今日入口

- 删除 `TodayPage`；`/` 改为重定向到 `/myday`。
- 启动落点 `/date/all` 不动。侧边栏前两项的位置也不动（全部任务、我的一天），“计划”占原来“日历”的第三位，老用户的位置记忆只有第三位之后才失效。
- `ReviewPage` 里“从回顾打开任务”的两处导航改为显式落到“全部任务”并把状态筛选设为“全部”（`navigate('/date/all', { state: { statusFilter: 'all' } })`），与数据看板数字卡片的写法相同。`CommandPalette` 里的“今天”一条改名为“我的一天”并指向 `/myday`。

实施中修正：起初设想保留 `ReviewPage` 的 `navigate('/')`，经重定向落到“我的一天”，并认为详情面板按任务 ID 打开、不依赖清单。真机上不成立——详情面板只对当前清单里的任务保持打开（`useDesktopTaskStatusFilter` 会清掉不在可见集合里的选中任务），而回顾里的事项不一定在“我的一天”里，也不一定是未完成的，表现为面板先打开、约 0.8 秒后被关掉。落到“全部任务 + 全部状态”后任何未归档的任务都能保持打开，比改动前（只有到期日是今天的任务能保持打开）更可靠。`/` 的重定向保留给其他可能的旧地址。
- `useTasks.ts` 里“加入我的一天时自动补截止日期”的行为不变，只更新注释里对今天页面的指代。`MyDayPage` 的“全部加入我的今天”改为“全部加入我的一天”。

备选：两个入口都保留，改名成“今天到期”和“我的一天”。两个清单仍然大面积重叠，也省不出一行。否决。

### D6 侧边栏的结构与两级样式

自上而下：顶行 48px → 目的地组（5 项，14px / 34px）→ 标签分组（标题 12px；条目 13px / 30px）→ 底部组（数据面板 13px / 32px，加原有的设置带）。固定部分合计约 358px，规格上限是 380px。

- 目的地与标签在字号、行高、颜色三方面都拉开。组与组之间靠留白分隔（组前 12–16px），去掉目的地组上下那两条 7% 透明度的细线；底部组自带底色，不需要分隔线。
- 标签分组标题变成可折叠的按钮，右侧保留“新建标签”。折叠状态是 `Sidebar` 的组件内状态，会话内保持，与“计划中”现在的做法相同。
- 颜色按角色取值，三组文字在六套主题下都不低于 4.5:1。现状与起始取值如下（按 WCAG 相对亮度公式核算；玻璃主题的底色按半透明深色叠在渐变上估算）：

| 角色 | 浅色 | 深色 / 玻璃 | 温暖石炭 | 浮光 |
|---|---|---|---|---|
| 分组标题·现状 | `#6B7280` 4.35 | `#6B7280` 3.67 / 3.87 | `#9E947A` 6.20 | `#6B7A8A` 3.79 |
| 目的地（未选中）·现状 | `#6B7280` 4.35 | `#C4C4CC` 10.25 / 10.80 | `#B8AA84` 8.12 | `#5F6C7A` 4.63 |

- 分组标题用新类 `.sidebar-section-label`（12px、600、去掉 `uppercase` 和字距），并在 warm、lumina 的覆盖表里各加一条；`.section-label` 不动。
- 目的地与标签的文字继续用“工具类加主题覆盖表”的做法。凡是引入的新色值类，都要在 warm、lumina 覆盖表里补上对应行，保持这两套主题的色相。
- 标签计数用 11px，颜色比标签名称更淡。不要求它达到 4.5:1：它是补充信息，点进标签页能看到同一个数字。

### D7 顶行合并，切换器不可用时回退到应用名

- 侧边栏顶行高 48px，放折叠按钮和切换器，不再有单独的品牌行。
- `WorkspaceSwitcher` 的展开形态去掉外层留白，以及按钮的边框和底色（静止时无边框，悬停才出底色），高度 36px。`data-testid`、`aria-*`、Portal 菜单和菜单里的全部说明文案都不变，菜单位置照旧按按钮的矩形计算。
- 切换器返回空的两个分支（非桌面环境、清单尚未返回）改为渲染调用方传入的回退内容，侧边栏传入应用名。不传回退内容时仍然什么都不渲染，现有的 `WorkspaceSwitcher` 测试不受影响。
- 折叠成图标栏的形态不变，它本来就没有品牌行。

备选：保留品牌行，只把切换器变轻。两行仍然占约 100px。否决。

备选：把切换器挪到侧边栏底部。底部已有数据面板和设置，也不是“工作区在左上角”的通行位置。否决。

## Risks / Trade-offs

- [看板与四象限从“一次点击”变成“两步”] → 视图跨目的地保持，习惯用看板的人选一次之后每个范围都是看板；命令面板提供直达命令；旧路由重定向。上线后看反馈，再决定要不要做“固定到侧边栏”。
- [全局视图会带到“我的一天”] → 这是列表 / 便签墙 / 一体式已有的行为；页头的视图入口始终显示当前视图名，一键切回；昨日未完成、建议、今日重点不受影响。
- [“我的一天”里的看板需要确定的高度] → 页面结构是“可滚动的中间区加清单区”。看板与四象限下把中间区改成纵向 flex，清单区用 `flex-1 min-h-0` 并给一个最小高度；上方区域较高时由页面滚动，不把看板压扁。这是本变更里唯一没有现成先例的布局，必须在真机上按六套主题、三档窗口高度验收。
- [窄窗口里页头变挤] → 视图入口带文字后比原来宽约 50px。`PageTitle` 的容器本来就能换行；验收时把窗口拉到最小宽度检查不重叠。
- [老用户找不到“明天”“未来 7 天”] → “计划”在第三位，进去默认就是“未来 7 天”，范围切换就在标题下方；会话内记住上次范围。
- [测试与快照] → `PageStates` 的视觉快照含 `TodayPage` 条目，要删掉过时条目并更新受影响的快照；`Sidebar`、`CommandPalette`、`DateFilterPage` 的测试按新结构改写。
- [回退到旧版本] → localStorage 里可能留下 `kanban`、`matrix`。旧版本的三目渲染把未知值当列表处理，页头按钮回落到列表图标，不会出错。

## Migration Plan

六个阶段依次进行，每个阶段单独提交、可独立发布：

1. 侧边栏样式与图标（两级层级、分组标题、图标、标签折叠、计数）。
2. “计划”：范围切换、侧边栏入口、记住上次范围。
3. 单一的今日入口：删今天页面、`/` 重定向、文案统一。
4. 顶行合并与底部组。
5. 视图迁移：视图类型与菜单、抽出看板与四象限、三个页面接入、旧路由重定向、命令面板。
6. 文档与真机验收。

第 5 阶段之前侧边栏是 7 行（五个目的地加仍在侧边栏的四象限、看板），第 5 阶段完成后是 5 行。回退按阶段回退提交即可，没有数据迁移，也没有后端改动。
