## Context

动机和产品范围见 [proposal.md](proposal.md)。本设计采用建议默认值形成可审查基线；README 的 R1–R6 尚待用户审核，修改选择后需同步调整设计、specs 和任务。

当前已核实：

- `TaskDetail` 在一个纵向页面排列标题／状态、属性、提醒、描述、子任务和底部时间信息；侧栏详情默认宽 540px、范围 400–800px，一体式视图复用同一详情组件。
- 任务结构只有当前状态、创建／更新时间，没有可靠的完成事件历史；`stats_commands.rs` 以 `updated_at` 计算今日完成和最近七天分布，详情“完成于”也使用该字段。
- 描述和子任务有既定编辑保存契约；AI 润色和拆解已有请求接续与结果预览，不能因页签切换丢失。
- 番茄钟主要保存本机专注分钟汇总，没有覆盖所有任务工作的逐段历史，不能据此计算完成比例或解释未完成原因。
- 备份会复制数据库，现有导入按业务表选择性合并；新增表被备份不等于已有导入能恢复它们。

## Goals / Non-Goals

**Goals:** 建立低负担的任务执行记录，提供来源可检查的日／周回顾；离线基础功能与模型调用分开；用明确的日期、覆盖和保存语义避免伪造历史。

**Non-Goals:** 本轮不扩大为外部活动采集、精确工时系统、完整审计系统或自动任务调度；不重写既有看板全部历史统计；不扩展首版同步协议。

## Decisions

### 1. 详情采用两个页签，默认内容

建议“任务内容／进展记录”，顶部保留标题、完成操作、核心属性摘要和主要操作。提醒、重复等放入可展开的“更多属性”；置顶、固定桌面、删除等收进“更多操作”。不增加第三个“AI”或“复盘”页签。

内容页保留描述和子任务；长描述支持展开／编辑，图片、表格等富文本能力保留。记录页包含主动输入入口、分页时间线和可选“含子任务”筛选；系统事件默认不混入手写记录，可显式切到事实事件。

备选的单页折叠可少一次切换，但长记录会继续拉长详情，故当前不采用。用户若选择该备选，应更新布局 spec。本轮不把一张双状态草图当成真实界面验收。

公共头部和页签可保持在详情容器顶部，正文单层滚动；不在长描述、时间线内叠加多个滚动区。400px 侧栏、一体式窄宽度和未来移动端都使用同一信息顺序，不增加第三列。切换任务默认内容；仅切换页签时保留各页签滚动与编辑状态。

### 2. 一条记录对应一个任务

顶层任务和已有子任务均可记录。根任务默认只看自己的记录，用户可选择“含子任务”；聚合时显示来源任务，同一条记录只出现一次。详情按当前父子关系查询，子任务移动后其记录跟随原任务；周期回顾按来源保存时的根任务归类，不因后续移动重写历史。父子任务完成仍各自独立。

正文采用纯文本，去除首尾空白后 1–2000 个 Unicode 字符；Enter 换行，按钮或 Ctrl+Enter 保存。不要求类型、百分比、卡点或下一步字段。日期默认今天，支持主动选择过去日期补记，补记日期不冒充创建时间，不支持未来日期。

草稿按任务保留在当前应用会话；切换页签／任务或暂时关详情不提交、不弹询问。进程退出后未保存草稿不承诺恢复，界面在输入区说明保存语义。用户保存成功前不清空正文；失败可直接重试。草稿保存标识用于去重，编辑使用期望版本防止晚响应覆盖新内容。

### 3. 手动记录与自动事实分开建模

建议实体如下，名称和具体字段可在实施时调整：

| 实体 | 关键内容 | 主要约束 |
| --- | --- | --- |
| `task_progress_records` | 稳定记录 ID、任务／保存时根任务、根标签快照、记录日期、正文、创建／修改时间、版本、删除标记 | 正文独立于任务描述；删除清除正文并保留最小去重标记 |
| `task_state_events` | 事件 ID、任务／当时根任务、状态转换、UTC 发生时间、本机顺序、来源、最小标题／标签快照 | 仅记录真实转换；不复制描述、附件或手写正文 |
| `task_history_coverage` | 数据集历史起点、导入／同步缺口和清理区间 | 覆盖状态先于统计及 AI 解释 |
| `period_reviews` | 周期／范围键、可编辑正文、事实摘要、来源引用及版本、事件统计截止、资料准备时间、覆盖说明、回顾版本 | 每个周期与标签范围一份当前保存稿；重新生成不自动替换 |
| 保存回执 | 操作 ID、请求指纹、结果 ID／版本、删除后的最小回执 | 重复保存去重，晚响应不恢复已删除内容 |

手写记录的日期由用户选择；事件时间由程序记录。新事件用 UTC 时间并保留当时本地日期／偏移，事件同刻时用数据库顺序确定先后。既有任务时间字段不在本轮整体改造。

### 4. 在共享写入边界记录状态转换

建议设置“保留本机任务状态历史”默认开启，并允许用户关闭后续事件留存；这一默认值列入 R3 审核。关闭不删除原历史、不影响手写记录和任务操作，重新开启不补猜关闭期间的活动，而在覆盖信息中保留区间缺口。

开启期间至少记录完成、重新打开、挂起、恢复进行、放弃和恢复使用；标题、标签、排序、截止日期的普通编辑不生成执行进展。相同状态重复写入不新增事件。

事件与其对应任务变化在同一事务内提交，失败时共同回滚。GUI、便签、MCP／CLI、循环任务创建流程中实际发生的任务状态转换走共同边界；不依赖前端按钮监听，也不因为查看或迁移生成历史转换。

迁移只记录历史开始可用的时点，不为旧已完成任务反填完成事件。恢复含真实事件的备份保留原事件时间与 ID；普通任务导入不以导入时刻补造完成事件。只收到其他设备当前状态时，该状态可作为“当前状态参考”，真实发生日期标记未知，不进入确定日期的完成计数；资料变化要使已准备的回顾标记有更新。

任务删除不抹掉已有最小状态事实，历史来源显示“任务已删除”并禁用打开；随任务删除的手写正文清除。主动清理事实历史时记录覆盖缺口，不把清理后的空白解释为没有活动。已保存回顾是独立文稿，来源删除后保留文稿并标记来源不可用。

### 5. 日期和统计由程序确定

日回顾用选定本地日期；周回顾用周一至周日的自然周。当前周期只统计到准备资料的时间，过去周期统计到周期结束；界面显示实际事件统计截止与时区。另存资料准备时间，两者不能混用：今天补记昨天的内容可以进入昨天的材料，但不能宣称昨天就已获取这条记录。使用时区对应的日期边界，不以固定 24 小时相加处理跨日。

标签默认全部，显式选择多个标签按任一匹配。事实事件和手写记录按保存时根任务的标签快照筛选；子任务按当时根任务归类，补记不猜测过去的标签。编辑正文不悄悄重分组。历史标签已删除仍可说明原范围；不据当前标签变更重写过去事实。

“本期完成”指期内有真实完成事件，且截至本期资料截止时点最近一次完成／重新打开事件仍为完成的去重任务。期内完成后重新打开的事项另列，重新完成后按同一任务计一次。根任务与子任务分列，不相加宣称完成同等数量的项目，不把放弃计为完成。不同循环实例按不同任务 ID 处理。

记录日期落在范围内即可成为进展材料；记录出现不代表完成任务，缺少记录不代表没有推进。跨任务聚合按当时根任务分组，同一记录／事件不可重复计数。覆盖完整、部分可用、资料缺失三种状态需可见；覆盖仅承诺本机可确认事实与明确恢复的历史，不承诺跨设备全量。

新回顾使用独立查询。既有看板历史统计保持原接口并说明属于旧口径，不能转作回顾的 AI 事实来源；详情“完成于”改读可确认的真实事件，无依据时显示“完成时间未记录”。

### 6. 回顾由事实页和可编辑文稿组成

独立回顾页从数据看板进入，日／周共用组件。基础页离线展示覆盖说明、程序计算的事实、选定范围的记录和来源；用户可直接写总结／复盘并保存。没有材料时仍允许手写，不把记录或 AI 作为前置条件。

AI 稿分为“总结”“复盘观察”“下一步建议”“待确认问题”。总结引用已有材料；用户未记录的原因只允许作为待确认解释，建议明确为建议。首版不提供一键写入新任务、改状态、改日期或改“我的一天”的动作。

同一周期／标签范围保留一份当前稿，更新需显式保存且检查文稿版本；重新生成、失败和取消都保留已有保存稿与用户编辑。先不建设全文版本历史、评分或连续复盘体系。

### 7. 有界上下文与来源引用

准备时固定日期、时区、范围、覆盖、统计和来源版本。工程建议上限：40 个根任务分组、每根最多 5 个子任务事实条目、60 条手写记录；标题至多 120 字，记录单次带入至多 400 字，最终请求体至多 128 KiB。记录正文在数据库中仍完整保留。

默认按日期后至前稳定选取带入项，相同时间以 ID 排序，用户可在所选范围内补入／替换。完整基础统计在本机计算；模型只解释实际带入的条目。界面展示范围总量、实际带入、子任务与记录的遗漏／截断，超限由用户缩小范围，不静默扩展、删减或后台分批调用。

只发送实际预览的文本、程序事实和可选的用户回顾重点（至多 300 字）；不读取附件、链接、其他应用或任务描述全文。用本次临时引用映射本地来源，数据库主键留在本机。

建议输出为四组有界纯文本项：总结至多 8 项、观察至多 5 项、建议至多 5 项、问题至多 5 项，每项至多 500 字；每项引用一个或多个本次已提供来源，原因未知时放入问题区。完整输出及引用通过本地校验后才显示为可保存稿；流式片段只显示进度。程序事实栏不由模型输出覆盖。结构和引用合法不证明语义正确，验收需人工检查样例中的证据与推测。

### 8. 快照保存与请求生命周期

复用既有默认模型快照、全局并发、取消、超时、窗口隔离与诊断；回顾请求用途独立标识。同一回顾范围同时至多一个请求，修改范围后旧请求不覆盖新页面，返回原范围可接续；取消后晚结果不写数据。

回顾是基于某次资料快照的文稿。生成后来源变化，界面显示“资料已有更新”，用户可重新准备，也可明确选择“按此快照保存”，并保留事件统计截止、资料准备时间和过期说明。来源删除不恢复正文，来源链接显示不可用。保存使用文稿期望版本和操作回执，冲突保留本地编辑，不自动覆盖另一份新稿。

保存记录／回顾只写自己的业务数据，不更新任务描述、状态或更新时间。手写记录、状态事实和已保存回顾建议长期保留，清理调用摘要与每日 AI 卡片不清理这些数据。未保存模型输出和请求正文只在当前会话内存在。

### 9. 本机首版、备份和恢复

Windows 先交付，domain／repository 契约兼顾 Android。建议首版新实体不进入同步，页面说明“本机资料”；其他设备现有任务同步照常，无法据同步快照还原远端实际完成时间。若审核改为同步首版，必须增加独立实体 ID、删除标记、顺序／去重和冲突契约，并调整本规划后实施。

备份必须覆盖已保存新业务表与来源关联。现有任务导入默认不导入进展／回顾；增加明确的“同时恢复进展与回顾”选择，兼容旧备份缺表。含回顾的恢复必须整批原子、校验来源和版本，相同 ID 相同内容跳过、相同 ID 内容冲突拒绝覆盖；保留原事件时间，不生成今日活动。模型配置、凭证引用和本机默认模型继续遵守现有导入隔离契约。恢复后重新校验覆盖、来源和请求会话。

## Risks / Trade-offs

- [本机资料无法覆盖所有设备活动] → 明示范围和缺口；R2 审核决定是否扩大为同步首版。
- [页签增加一次切换] → 默认内容，保留操作和编辑状态，验证窄侧栏与一体式容器；不自动切到进展。
- [记录变成负担] → 单文本框、主动保存、不插入任务操作流程、无默认提醒或连续记录指标。
- [旧统计与新回顾不一致] → 新查询有覆盖起点和明确口径，旧图表不作为回顾依据，不回填猜测历史。
- [模型有引用仍可能误读] → 原始来源可打开，原因未知展示待确认，使用虚构代表样例做语义评审。
- [长期数据和来源删除] → 分页查询；清理后记录覆盖缺口；删除正文与旧稿来源状态有明确语义。

## Migration Plan

1. 审核 README 的建议默认值，并同步修订三个 specs 与任务；实施前记录最终选择。
2. 备份后增加新表、覆盖起点和索引，不回填旧完成事件；迁移和旧库恢复先用虚构／隔离数据库验证。
3. 交付布局、手动记录和状态事件，检查所有本机写入口与不使用记录的完整路径。
4. 交付本机日／周事实、手写回顾与备份恢复，再交付 AI 生成、来源检查和保存。
5. 完成代表内容的真实 Windows 界面验收、必要回归及真实模型样例审阅；规划完整和单元测试通过均不代表产品验收完成。
6. 发布回退优先关闭新入口、保留新业务表并提供兼容导出／恢复；不以删除新表作为回退。跨新数据版本恢复需先校验版本，不直接覆盖模型配置。
