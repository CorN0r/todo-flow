## Context

动机与范围见 [proposal.md](proposal.md)。本稿为待用户审核的具体设计，不表示已确认实施。

R2 修订依据：用户明确“我的一天”应是每天选择后的结果，同时规则推荐必须保留，未接入 AI 时仍依赖规则推荐。本稿保留规则为基础路径，AI 是可选增强；AI 默认范围为全部可执行任务、支持标签收窄，并明确每日切换与当天已选安排的边界。

当前代码约束：

- `MyDayPage` 的既有建议查询为未完成、今天或之前到期的根任务，`myDaySuggestions.ts` 再按状态、优先级与截止日期处理。
- `useToggleMyDay` 对无截止日期的任务补写今天；Rust 的 `add_task_to_my_day` 和 `task_repo::update` 可以只改 `my_day_date`。新流程需要保留这个区别。
- 任务仅有全局 `sort_order`，没有每日行动顺序、预计耗时、目标或进度字段。
- 已有 AI gateway、两并发槽、取消与请求标识、结构化错误、调用摘要、拆解预览与采纳保护；前端会话 store 可跨页面保留请求。
- 既有 AI 输入与候选不长期保存；已采纳子任务属于明确的业务结果。新功能沿用该边界，保存用户采纳后的行动卡，不保存完整模型回复。
- 本次工作区已有子任务描述相关未提交修改。规划只新增本变更目录；实施阶段需在这些改动基础上合并，不能覆盖。

## Goals / Non-Goals

**Goals:**

- 提供从明确范围选出少量行动、解释取舍、确认采纳、开始执行的完整闭环。
- 程序约束候选与写入，模型负责在候选内给出语义建议。
- 已有日期、状态、任务正文、全局排序和手动清单保持各自语义。
- 复用现有模型设施，补齐多任务、跨日、批量采纳和本机行动结果契约。

**Non-Goals:**

- 不新增估时字段、日历时段、自动延期、目标图谱、进度日志、复盘或 Agent 执行。
- 不把自然语言“今天只有一小时”解释成已经严格满足的容量预算；本轮不输出预计耗时。
- 不改造所有手动加入“我的一天”的旧行为，不重构现有状态过滤和全局排序。
- 不同步 AI 行动卡，不提供历史计划界面；Android 不实现新 UI。

## Decisions

### 1. “今日重点”独立于原有清单

Windows“我的一天”保留原规则推荐、原有任务清单与操作，增加可选的 AI 建议和已采纳“今日重点”。界面采用同一建议区域内“规则推荐 / AI 建议”模式切换，避免两个长列表同时展开；共享展示区域不意味着移除规则能力。状态筛选与视图切换继续作用于原有清单。

“我的一天”表示用户今天已选择的结果。默认候选来自全部可执行任务，可按标签缩小；当天清单为空不是候选为空，也不阻止准备推荐。

首次进入、新一天或重启时默认展示规则推荐；配置模型不会改变默认模式。规则推荐独立于模型配置、网络与 AI 状态，保留现有日期/优先级逻辑以及加入、暂不和重新推荐行为。未配置模型的用户可一直按原流程使用，不需要先尝试 AI 或处理 AI 错误。

用户主动切换到 AI 建议并点击生成后才发起模型调用。已配置模型的用户也可继续使用规则推荐；AI 失败或取消时保留已有有效 AI 预览，规则推荐仍可随时切回，两侧状态不互相清空。界面明确来源，不将规则结果当成 AI 输出。

AI 的标签范围、候选调整、重点输入和必做/排除约束只作用于 AI 模式，不暗中改写原规则推荐的查询或会话排除状态。两者采纳都能形成普通今日任务归属，但现有规则加入行为保持原样，AI 采纳仍遵循本变更的字段保护语义。

首版默认推荐至多 3 个根任务，每个根任务只占一张卡，可以指向其中一个已存在的未完成子任务。行动卡表达“这次推进哪一步”，不代表今天承诺完成整个父任务。

顺序仅作用于行动卡，不写全局 `sort_order`。采纳添加今日归属，不移走未选中的原有事项。界面显示“本轮重点 X 项，原有清单另有 Y 项”，不把“未入选”写成“今天不用做”。

现有“今天”页按截止日期过滤，AI 加入无截止日期事项后只保证它出现在“我的一天”，不因此出现在“今天到期”。这是本稿有意区分的语义，需在审核中一并确认，不顺带改造“今天”页。

不采用直接替换整个清单的方式，因为那会把模型取舍变成移除用户既有安排；不采用全局重排，因为会影响其他任务视图。

### 2. 范围先于模型调用

提供两个范围：全部可执行任务、指定标签。默认全部可执行任务，用户可以主动收窄；本日会话保留上次选择，重启或跨日后恢复默认。多标签按任一匹配，子任务只继承入选父任务的上下文，不因为子任务标签匹配而越出根任务范围。“当前我的一天”不再作为推荐范围选项，而以“已加入”事实表达今天已有的选择。

首次打开不自动发请求。程序先在本机按默认或用户选定范围准备候选，展示清单、数量、被截断的信息与当天已加入标记，再由用户点击生成。选定标签下为空时允许恢复全部；全部可执行集合为空时说明没有候选，不发送空请求。“全部”是本机候选搜索范围，不代表全库正文都会发送给模型。

候选根任务必须未删除、未归档、未完成、未挂起、未放弃，沿用共享状态规则。先过滤再限量，不能先拿全部任务发给模型再让模型排除。

在范围内按以下组别去重取候选：用户显式补入项、超期、未来 7 个本地自然日内到期、置顶或高优先级、无截止日期、其他事项。同一组按优先级降序、有效截止日期升序、创建时间升序、ID 稳定排序；无日期排在有日期之后。不能仅因任务已在今日清单就让其抢先占满候选。用户可在当前范围内手动补入遗漏任务，但不能用补入绕过状态和范围检查。

当日已选是用户已有安排，不自动等同于“必做”，也不作为唯一候选来源。已选任务进入本次候选时标记“已加入”，模型可以为它推荐下一步，采纳摘要区分“已在今日”与“本次新增”。所选标签以外的已选事项只提供剩余数量提示，不额外发送其正文；推荐未覆盖的已选事项仍保留。

每次至多带入 20 个根任务；界面说明范围内合格总数、实际使用数与未带入数，不宣称扫描并比较了全部事项。限量造成遗漏时允许用户调整范围或替换候选。

### 3. 有限且可检查的上下文

只发送选定候选的标题、日期、优先级、今日归属、置顶事实、相关说明文本与现有可执行子任务摘要，以及用户输入的今日重点、必做和排除约束。不读取附件、链接、图片、私人记录或其他应用。

初始上限为根任务标题 120 字、说明 300 字；每根至多 5 个可执行子任务，标题 120 字、说明 100 字。默认按现有子任务顺序取前 5 项，候选详情允许用户替换纳入的子任务，不改原任务顺序。界面标出文本截断及未带入子任务数量。

最终序列化请求体上限 128 KiB；超限在本地停止并提示缩小范围，不能在发送时静默丢任务。上限是本稿工程默认值，可在审核中调整。

数据库主键留在软件内；对模型使用本次快照的临时引用，例如 `t01` 与 `t01.s02`。本机映射负责还原真实任务和父子关系。任务原文作为数据处理，不允许它扩大输入范围或改变写入规则。

### 4. 可选重点与明确约束

“今天想推进什么”是可选输入，上限 300 字；没有目标输入也可按候选任务事实推荐。用户可设置推荐项数 1–5，默认 3，并在候选中标记必做或本次排除。

必做项与排除项不能重叠；必做数量超过目标项数时先要求调整，不调用模型。模型结果必须覆盖全部必做项，且不得包含排除项。

“换一件”把当前卡对应根任务加入本次排除集合；如果该卡先前标为必做，同步解除其必做标记并在界面显示变化，保留其他用户锁定的根任务后重新生成。候选不足时说明原因，不补造任务。选定范围和用户约束在后端再次校验，不仅依赖前端。

必做约束用于约束 AI 生成；用户仍可在采纳预览中手动取消某项，变更摘要明确显示其未被采纳，用户的最终选择优先。

### 5. 结构化建议与可编辑结果

模型输出包含 `assumptions`、`actions` 和可选 `not_selected`。每个 action 包含根任务引用、可空的现有子任务引用、推荐理由、下一步行动、停止标准；`not_selected` 最多解释 3 项取舍，仅作为说明。

动作数量为 1 至目标项数，不能重复根任务；子任务必须属于该根任务且存在于此次候选快照。标题、日期和优先级等事实由软件用真实数据展示，模型不能提供新的任务实体或字段变更。

理由上限 200 字、下一步和停止标准各 300 字；假设至多 5 条、每条 200 字；取舍理由每条 200 字。所有字段为纯文本，完整结束且本地校验通过后才出现可采纳卡片。未知引用、错误父子关系、遗漏必做项、包含排除项或内容截断均不产生可采纳结果。

信息不全时先建议并单列假设。只根据明确输入描述等待和依赖，不能把推测包装为已确认的事实。结构校验不能证明推荐语义正确，因此用户可修改下一步、停止标准、顺序和勾选状态。

不把下一步自动另建为任务，也不回写或润色原说明；已有描述润色和拆解仍是独立功能。

### 6. 两阶段准备与生成

拟在现有 AI repository 增加下列业务契约，命名可按实现约定细化：

| 操作 | 输入与结果 |
| --- | --- |
| prepareMyDayContext | 日期、范围、候选/子任务选择；返回本机候选预览、数量、截断说明、contextId 与当前已采纳计划版本 |
| generateMyDayPlan | contextId、今日重点、必做、排除、目标项数、requestId；返回已校验 proposal、模型快照和关联请求信息 |
| applyMyDayPlan | proposalId、operationId、选中的已编辑行动卡顺序、期望计划版本；返回本次添加的根任务 ID、计划标识/版本及重复处理标记 |
| getMyDayPlan | 本地日期；返回当日已采纳行动卡及当前关联任务状态 |
| clearMyDayPlan | 本地日期、期望版本；清空行动卡并递增版本，不移除清单中的任务 |

context 与 proposal 仅驻留内存。输入或范围变动后，旧候选不能悄悄当成新请求结果；生成前更新快照。会话中离开页面可继续生成、返回可接续；退出应用后未采纳预览过期。

### 7. 复用运行时，区分多任务请求作用域

新请求用途记为 `my_day_plan`，复用默认模型与不可变配置快照、全局两并发槽、取消、进度、超时和错误。每个本地日期同时只允许一个规划请求，不占用伪造的数据库任务 ID 作为锁或诊断关联。

本机存在今日计划生成时拒绝重复发起；其他任务的润色/拆解仍按原任务互斥，并共享全局并发上限。进度按 requestId 关联，晚响应不能覆盖新会话。

流式只展示生成状态与进度，不能从半份 JSON 创建卡片。重新生成失败或取消保留原有有效预览；原有已采纳计划始终保留到新采纳成功。网络期间不持有数据库锁。

现有模型验证不等于本功能语义验收。增加本功能固定虚构任务的开发验收样例，不强制重构设置页验证类型；测试调用仍经过明确触发。

### 8. 日期、任务与计划版本共同约束采纳

准备和采纳使用软件当前本地日期；模型不计算“今天”。跨午夜或时区变化使目标日期不再为今天时，新采纳返回过期提示，要求重新准备，不补写昨天或悄悄顺延到明天。

按日期刷新只切换当天选择结果，不删除任务或清理其截止日期。昨日未完成重新作为普通可执行任务参加候选筛选，不自动复制到今天；旧预览、今日重点输入与必做/排除约束在跨日后失效，候选范围恢复全部。既有“昨日未完成”提示可以保留供手动选择，但不能成为默认唯一候选池。跨日刷新不自动调用模型。

使用完整的本机任务内容计算指纹，不能仅比较秒级 `updated_at` 或发给模型的截断说明。采纳在事务内复核选中根任务及目标子任务的内容、状态、父子关系、范围成员关系、今日归属和期望计划版本。

已选内容变化则整批拒绝并保留预览。非选中候选变化不单独阻断采纳，但界面可提示范围已有变化、允许重新生成。新加入候选范围的任务不会被宣称已经参加此前比较。

### 9. 追加清单并原子替换本机重点

同一事务内检查回执与提交摘要、检查本批是否采纳过、校验日期/版本/选中任务、为尚未加入今天的根任务设置 `my_day_date`、记录其普通任务同步操作、保存行动卡新版本和采纳回执。任一步失败全部回滚，提交后统一通知界面刷新。

只更改选中根任务的今日归属；目标子任务只是行动入口，不额外作为一个根任务计数。已有今日任务保持原样，不改截止日期、提醒、优先级、正文、完成状态、来源标记或全局排序。

不调用前端 `useToggleMyDay`，也不在前端循环逐条写入。可复用 `task_repo::update` 的保留字段语义及同步记录机制；新入口采用专用后端事务。

一份 proposal 只成功采纳一次。同一 operationId、相同提交内容返回已存结果；不同内容或已被其他 operationId 采纳返回冲突。回执先于内存候选检查，以支持成功后响应丢失的重试。

卡片保存的后续检查指纹以事务内今日归属写入后的状态计算，不沿用写入前快照，避免采纳自身立刻使所有卡片失效。

已有本机计划时，新采纳替换“今日重点”卡片，预览显示增加、保留与移出重点的差异；移出重点不会移出普通“我的一天”。清除重点同样不撤回任务归属，并递增计划版本，阻止旧预览重新覆盖。

### 10. 专用本机结果数据

拟增加三张本机表，不改 tasks 领域字段，不加入同步实体白名单：

| 对象 | 主要信息 |
| --- | --- |
| ai_my_day_plans | 本地日期唯一、计划 ID、revision、用户明确采纳的今日重点文本、模型名称快照、生成与采纳时间、清除状态 |
| ai_my_day_actions | 计划 ID、显示顺序、根任务 ID、可空目标子任务 ID、采纳后的下一步/停止标准/理由、关联任务指纹 |
| ai_my_day_apply_receipts | operationId、唯一 proposalId、目标日期、提交摘要、结果计划 ID 与版本、发生写入的根任务 ID |

任务引用采用可失效的逻辑关联，不因计划历史而阻止任务删除。读取时联查实时任务，不能用过期的标题和状态伪装成仍可执行。

采用专用回执，因为当前 `ai_apply_receipts` 面向创建子任务，包含父任务与新建 ID 的特定含义。新结果不混入旧回执，避免破坏拆解行为。

首版只展示当天计划；已采纳结果和专用回执保留最近 30 个本地日期，按日期成组清理，清理不修改普通任务。重试过期日期的新操作不会执行写入；既有回执重放只返回原结果，不恢复后来已清除/替换的计划。前端采纳后重新读取当前计划，不能直接用旧回执覆盖当前显示。

本地保存的是用户确认后的行动结果，非原始请求或整份模型输出；未采纳候选、被丢弃的假设与全量输入不落库。清理调用摘要不影响计划结果与回执。任务跨端同步只携带普通今日归属，另一设备没有这些 AI 卡片。

### 11. 开工入口与实时失效

已采纳的卡片提供打开任务、开始专注两个入口；未采纳预览只用于检查、调整与选择，不直接启动专注。指向有效子任务时打开并聚焦该子任务，番茄钟关联子任务；否则关联根任务，复用现有专注配置。

已有专注运行或暂停时，不直接覆盖 `startTimer` 状态，提示用户先处理当前专注，保留现有控制方式。开始专注前重新确认关联任务仍可执行。

目标子任务完成时只标记本步完成，不推断父任务完成；父任务完成/删除/挂起/放弃、被移出当天或目标子任务失效时卡片显示具体状态并禁用开始，不重新添加、不自动选择另一个任务。内容变化标记需检查，可打开详情或重新建议。

独立卡片不改变下方任务列表状态计数。若当前列表筛选隐藏了目标，提供明确的“切到进行中并定位”操作，不静默切换原筛选；卡片打开详情也不能绕过现有详情选择规则。

### 12. 审核、试用与验证范围

审核重点见 README 的 R1–R6。本稿已经为每项选定建议方案，因此没有把会影响规格和任务拆分的关键问题悬置为技术开放问题；用户审核后统一修订全部产物。

先用虚构清单做适配和事务验证，再在用户授权的真实模型上验证 5 组样例：无日期重要任务、全部紧急、多个父子任务、候选不足、用户必做/排除。结构通过和用户认可推荐质量分别记录。

小规模试用关注打开页面到首次开始行动的耗时、采纳后是否开始、选择更换的原因与超额安排感受。首版通过人工试用记录或明确的轻量计数评估，不增加隐式正文采集或全量埋点工程，不以新增任务数衡量成功。

## Risks / Trade-offs

- [模型会输出像样但不适合今天的建议] → 理由、下一步和停止标准可检查；日期事实由软件展示；用户可锁定、排除与更换，质量另行验收。
- [全部范围较大或候选限量遗漏重要任务] → 本机先筛选，展示实际候选和遗漏数，支持标签收窄与手动替换，不把全库正文自动发送给模型。
- [规则推荐被误降级为只有 AI 失败才可用] → 原规则是默认独立路径，AI 仅按需增强；未配置、不使用、离线或调用失败都保留规则及其操作，已配置模型也不强制切换。
- [AI 重点少于原清单导致“安排得下”的错觉] → 同屏提示原清单其他事项；首版不宣称容量预算或完整排程。
- [旧加入 hook 会改变无日期任务] → 新事务入口只写今日归属，并把无日期保持不变列为强制验收项。
- [多任务或跨日导致预览过期] → 采纳复核选中任务、日期与计划版本；失败不写一部分，保留预览。
- [行动卡本机保存导致跨端体验不同] → 明确 Windows 首版，普通今日任务同步，AI 顺序与行动说明不跨端。
- [保留已采纳文本会增加少量本地数据] → 仅保存明确业务结果，30 日清理；不保存未采纳全文，不加入任务导入或同步。

## Migration Plan

1. 审核通过后再实施；按当时最新迁移版本新增三张本机表及唯一约束，不写死本稿检查时的迁移编号。
2. 扩展 AI 契约、原生业务、测试替身与页面，保持旧模型配置、拆解和润色 API 的行为。
3. 迁移不改存量任务的日期、排序或今日归属；现有任务库导入不导入或覆盖本机计划表，整库备份可包含本机已采纳结果。
4. 完成针对性自动检查与 Windows 应用内虚构任务验收后开放 AI 入口。只有 AI 模式需要模型配置，规则推荐和手动清单不依赖它；覆盖无模型、已配置但不使用、离线及 AI 失败的独立可用验收。
5. 如实现验收失败，可关闭新入口并保留新增表及用户已采纳的普通今日归属；不自动反向移除用户任务或破坏原有模型功能。
