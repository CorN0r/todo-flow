## MODIFIED Requirements

### Requirement: 本机保存与可恢复的数据生命周期

首版记录、事件及覆盖信息 MUST 持久保存在本机，不新增同步实体；Android MUST NOT 出现可点击但无法执行的新入口。已保存记录和事实 MUST 长期保留至主动删除或清理，不随 AI 调用摘要、每日重点或跨日刷新清理。删除记录或任务关联的手写正文 MUST 清除正文；最小去重标记可保留。任务删除后最小历史状态事实可保留，来源 MUST 标记不可打开；主动清理事实后 MUST 标记覆盖缺口。

备份 MUST 包含新业务数据及来源关系。从备份找回任务时，所选任务及其子任务在本机缺失的进展记录与真实事件 MUST 随任务带回并保留原 ID、时间和来源；随任务删除而被清除正文的记录 MUST 按备份恢复，使找回的任务连同它的历史一起回来。本机上仍有效的同 ID 记录与事件 MUST NOT 被改写，未被找回任务的本机记录 MUST NOT 被改动。用户显式选择同时恢复日／周回顾时，MUST 校验版本和引用、原子恢复、跳过内容一致的同 ID 数据，并拒绝不同内容的同 ID 覆盖；旧备份缺少新数据 MUST 可兼容。恢复 MUST NOT 改写本机模型配置或伪造今日活动。

#### Scenario: 清理 AI 调用摘要
- **WHEN** 用户清理模型调用摘要或每日 AI 卡片到期
- **THEN** 已保存进展和事实历史仍存在，未保存模型输出不会被恢复

#### Scenario: 备份后恢复
- **WHEN** 用户从含进展资料的备份找回任务，并显式选择恢复日／周回顾
- **THEN** 所选任务缺失的记录和事件随任务恢复，回顾文稿一致恢复，事件保持原时间，重复执行不重复计数，本机模型选择不被覆盖

#### Scenario: 恢复冲突或历史清理
- **WHEN** 恢复遇到相同 ID 不同内容，或用户主动清理某段事实历史
- **THEN** 恢复冲突不产生部分覆盖；主动清理后的该时段标为部分资料可用，不误报为无活动

#### Scenario: 本机有效的记录不被改写
- **WHEN** 用户找回一个当前库中已存在、且本机仍有有效的进展记录或状态事件的任务
- **THEN** 本机有效的记录与事件保持原样，只补充本机缺失的

#### Scenario: 误删任务的历史一并回来
- **WHEN** 用户找回一个在本机删除的任务，删除时它的进展记录正文已被清除
- **THEN** 这些记录按备份恢复，内容与时间与备份一致；事件只增不改
