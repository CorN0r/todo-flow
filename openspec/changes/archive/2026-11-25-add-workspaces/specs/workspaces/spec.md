## Purpose

让用户把不同用途的数据分成互相独立的工作区并在应用内管理：每个工作区拥有自己的任务、标签、习惯、设置与附件目录，同一时间只激活一个；除明确确认的删除外，管理操作不破坏任何现有内容。

## ADDED Requirements

### Requirement: 独立的数据空间

系统 MUST 把每个工作区保存为独立的数据库文件及其专属附件目录。任务、标签、习惯、提醒、桌面便签、进展记录与回顾、AI 模型连接配置、同步状态以及保存在库内的设置 MUST 归属各自的工作区；对一个工作区的任何操作 MUST NOT 改动另一个工作区的数据。主题、任务视图模式和番茄钟记录属于应用，MUST NOT 因切换工作区而改变。

#### Scenario: 两个工作区互不影响
- **WHEN** 用户在“工作”中创建任务并修改键盘快捷键，然后切到“个人”
- **THEN** “个人”的任务、标签和键盘快捷键与其此前状态完全一致

#### Scenario: 外观不随工作区变化
- **WHEN** 使用深色主题和列表视图的用户切换到另一个工作区
- **THEN** 主题与任务视图模式保持不变

### Requirement: 工作区清单与唯一激活

系统 MUST 在所有工作区之外保存工作区清单，记录名称、数据位置、最近使用时间和当前激活项；清单 MUST NOT 进入任何工作区的备份或同步。同一时间 MUST 只有一个激活的工作区，清单中 MUST 至少保留一个工作区。名称去除首尾空白后 MUST 唯一且不区分大小写。应用启动时 MUST 打开上次激活的工作区。清单缺失或无法解析时，系统 MUST 依据磁盘上已有的数据重建清单，MUST NOT 删除、移动或改写任何数据库文件。

#### Scenario: 启动时打开上次的工作区
- **WHEN** 用户上次使用“工作”后关闭应用，再次启动
- **THEN** 应用打开“工作”，界面显示它的内容

#### Scenario: 名称仅大小写不同
- **WHEN** 用户新建或重命名工作区，名称与已有名称仅大小写不同
- **THEN** 系统拒绝并提示名称已被使用，现有工作区不变

#### Scenario: 清单文件损坏
- **WHEN** 清单文件内容无法解析
- **THEN** 应用仍能启动并依据磁盘上的已有数据列出工作区，数据库文件与附件目录保持原样

### Requirement: 升级后原地登记

升级到包含工作区的版本后首次启动，系统 MUST 把既有数据原地登记为“默认工作区”，MUST NOT 移动或复制既有的数据库文件和附件目录；数据库结构升级按原有机制进行。

#### Scenario: 从旧版本升级
- **WHEN** 用户从旧版本升级后首次启动
- **THEN** 任务、设置与附件与升级前一致，清单中只有一个“默认工作区”，数据仍在原位置

### Requirement: 新建空白工作区

系统 MUST 允许新建数据为空的空白工作区，名称 MUST 满足唯一性规则。语言、键盘快捷键、桌面小组件位置等库内偏好 MUST 从当前工作区复制；任务、标签、习惯、AI 模型连接及其默认选择 MUST NOT 复制。

#### Scenario: 新建后内容为空而偏好一致
- **WHEN** 用户在“默认工作区”中新建“试验”
- **THEN** “试验”没有任何任务、标签、习惯和模型连接，语言与键盘快捷键与“默认工作区”相同

### Requirement: 从文件添加工作区

系统 MUST 允许把一个数据库文件添加为新工作区：文件 MUST 先通过校验，再被复制到应用的托管位置；系统 MUST NOT 以引用原路径的方式添加，原文件 MUST NOT 被修改、移动或删除。新工作区 MUST NOT 继承任何其他工作区的内容，名称默认取文件名并可修改。比当前应用旧的文件 MUST 可以添加，结构升级 MUST 只作用于复制后的副本。

#### Scenario: 添加一份备份
- **WHEN** 用户选择一份备份文件添加为工作区
- **THEN** 备份文件的字节内容不变，新工作区的任务、标签、设置与备份一致，且不包含其他工作区的任何内容

#### Scenario: 添加旧版本的备份
- **WHEN** 用户添加由更早版本应用生成的备份
- **THEN** 添加成功，副本被升级到当前结构，原文件不变

#### Scenario: 文件正被其他进程使用
- **WHEN** 所选文件正被一个运行中的 MCP 进程使用
- **THEN** 添加得到的工作区包含该进程已写入的全部数据

#### Scenario: 校验不通过
- **WHEN** 用户选择的文件不是 TodoFlow 数据库、未通过完整性检查，或结构版本高于当前应用
- **THEN** 系统拒绝添加并说明原因，不产生新工作区，现有数据不变

### Requirement: 重命名工作区

系统 MUST 允许重命名工作区；重命名 MUST NOT 改变数据位置、激活状态或任何内容。

#### Scenario: 重命名当前工作区
- **WHEN** 用户把当前激活的“试验”改名为“Agent 试验”
- **THEN** 切换器与管理界面显示新名称，任务数量与内容不变，它仍是当前工作区

### Requirement: 删除工作区

系统 MUST 在用户明确确认后才删除工作区，确认界面 MUST 显示名称与任务数量。删除 MUST 移除该工作区的数据库文件、附件目录和清单条目，MUST NOT 影响其他工作区的任何数据。系统 MUST 拒绝删除最后一个工作区。删除当前激活的工作区时，系统 MUST 把最近使用的另一个工作区设为激活项。因文件被其他进程占用等原因无法完成时，系统 MUST 不留下半完成状态，并提示原因。

#### Scenario: 删除非当前工作区
- **WHEN** 用户确认删除非当前的“试验”
- **THEN** “试验”的文件、附件目录和清单条目被移除，当前工作区与界面不变

#### Scenario: 删除当前工作区
- **WHEN** 用户确认删除当前激活的工作区，且还有其他工作区
- **THEN** 最近使用的另一个工作区成为激活项，应用重启后打开它

#### Scenario: 重启后文件仍被占用
- **WHEN** 用户确认删除当前激活的工作区，重启后它的数据库文件仍被其他程序占用
- **THEN** 该工作区保留在清单中，启动时提示关闭占用它的程序后重试，其他工作区照常可用

#### Scenario: 只剩一个工作区
- **WHEN** 清单中只有一个工作区
- **THEN** 系统拒绝删除并说明至少保留一个

#### Scenario: 文件被占用
- **WHEN** 待删除的数据库文件正被其他进程占用
- **THEN** 删除不产生半完成状态，清单条目仍可用，系统提示关闭占用它的程序后重试

### Requirement: 删除工作区时的凭证清理

删除工作区时，系统 MUST 删除为该工作区的 AI 模型连接保存、且不被任何剩余工作区引用的 API Key；仍被其他工作区引用的 MUST 保留。删除未能完成时 MUST NOT 改动任何 API Key，除删除以外的管理操作 MUST NOT 改动任何 API Key。

#### Scenario: 清理独占的密钥
- **WHEN** 被删除的工作区有一个其他工作区都没有的模型连接
- **THEN** 该连接保存的 API Key 从系统凭证存储中清除

#### Scenario: 保留共用的密钥
- **WHEN** 两个来自同一份备份的工作区引用同一个模型连接，用户删除其中一个
- **THEN** 另一个工作区的该模型仍显示为已配置且可以调用

#### Scenario: 删除未完成时不动密钥
- **WHEN** 删除因文件被占用而没有完成
- **THEN** 该工作区的 API Key 保持不变

### Requirement: 管理界面与当前工作区可见

系统 MUST 提供工作区管理界面，列出每个工作区的名称、任务数量、最近使用时间和当前标记，并提供新建、添加、重命名、删除与切换入口。主界面 MUST 始终显示当前工作区的名称，侧边栏折叠时也不例外。

#### Scenario: 侧边栏折叠
- **WHEN** 用户把侧边栏折叠为图标栏
- **THEN** 仍能看到当前工作区的名称

#### Scenario: 任务数量准确
- **WHEN** 用户打开管理界面
- **THEN** 每个工作区显示的任务数量与打开该工作区后“全部任务”的数量一致

### Requirement: 备份作用于当前工作区

“备份到文件”MUST 导出当前激活工作区的数据库，MUST NOT 包含其他工作区的数据，也 MUST NOT 包含 API Key 本体。

#### Scenario: 备份当前工作区
- **WHEN** 用户在“工作”中执行备份
- **THEN** 导出的文件只包含“工作”的数据

### Requirement: 附件文件的归属与缺失

附件文件 MUST 保存在各自工作区的附件目录。备份文件和被添加的数据库文件本身 MUST NOT 被视为携带附件文件。对于记录存在而文件缺失的附件，界面 MUST 显示明确的“文件缺失”状态，MUST NOT 把它呈现为可打开的附件，也 MUST NOT 出现未处理的错误。

#### Scenario: 添加的工作区带有附件记录
- **WHEN** 用户添加一个含附件记录的工作区并打开对应任务
- **THEN** 这些附件显示“文件缺失”，任务其余内容正常显示

### Requirement: 提醒只对当前工作区生效

系统 MUST 只为当前激活工作区的任务计算和弹出提醒，未激活工作区的提醒 MUST NOT 弹出。工作区被激活时，系统 MUST 立即检查它的到期提醒，包括未激活期间到期的提醒，处理方式与“应用关闭期间漏掉的提醒”一致。切换界面 MUST 说明未激活工作区的提醒不会弹出。

#### Scenario: 未激活的工作区不提醒
- **WHEN** “工作”的一个任务在“个人”激活期间到期，用户随后切换到“工作”
- **THEN** “个人”激活期间不弹出该提醒；切换完成后立即弹出

#### Scenario: 规则可见
- **WHEN** 用户打开切换器
- **THEN** 能看到“只对当前工作区提醒”的说明

### Requirement: 文件校验

“添加工作区”与“从备份找回”MUST 使用同一套文件校验：文件是 TodoFlow 数据库、通过完整性检查、结构版本不高于当前应用。任何一项不满足时，系统 MUST 拒绝操作并说明原因，现有数据 MUST 零改动。校验 MUST NOT 修改源文件。

#### Scenario: 更新版本生成的文件
- **WHEN** 文件由比当前应用更新的版本生成
- **THEN** 系统拒绝并提示先升级应用

#### Scenario: 损坏的文件
- **WHEN** 文件未通过完整性检查
- **THEN** 系统拒绝并说明文件可能已损坏

#### Scenario: 校验不改动源文件
- **WHEN** 用户校验并添加一个旧版本的备份
- **THEN** 原文件的内容与修改时间都不变
