## Purpose

让用户从备份文件中有选择地把任务找回当前工作区：先预览、再勾选，默认只找回当前库中没有的任务，不改动已存在的任务，也不改动本机的设置、模型配置、同步状态和日／周回顾（除非显式选择）。

## ADDED Requirements

### Requirement: 先预览再找回

系统 MUST 在执行前展示备份中的任务预览，包含子任务，并逐项标明该任务是“当前库中没有”还是“当前库中已存在”。用户 MUST 能逐项勾选。预览 MUST NOT 修改当前工作区，也 MUST NOT 修改备份文件。

#### Scenario: 预览标明差异
- **WHEN** 用户选择一份备份，其中 120 个任务有 8 个在当前库中不存在
- **THEN** 预览标出 8 个“当前库中没有”和 112 个“已存在”

#### Scenario: 预览后取消
- **WHEN** 用户打开预览后取消
- **THEN** 当前工作区与备份文件都没有任何变化

### Requirement: 默认只找回当前库中没有的任务

默认勾选状态 MUST 为：当前库中没有的任务已勾选，已存在的任务未勾选。执行后，被勾选且当前库中没有的任务 MUST 出现在当前工作区，并保留标题、描述、状态、截止时间、优先级、标签关联、“我的今天”归属、创建与更新时间，以及“由 Agent 创建”的来源标记。未勾选的任务和所有已存在的任务 MUST NOT 被改动。

#### Scenario: 找回误删的任务
- **WHEN** 用户误删“写周报”后从昨天的备份执行默认找回
- **THEN** 任务重新出现，内容、标签、创建时间与删除前一致；由 Agent 创建的任务仍带来源标记

#### Scenario: 不改动已有任务
- **WHEN** 用户对含 112 个已存在任务的备份执行默认找回
- **THEN** 这 112 个任务的内容、状态和更新时间与执行前一致

#### Scenario: 取消全部勾选
- **WHEN** 用户取消全部勾选并执行
- **THEN** 当前工作区没有任何变化

#### Scenario: 重复打开同一份备份
- **WHEN** 用户找回后再次打开同一份备份的预览
- **THEN** 上次找回的任务显示为“已存在”且未勾选，再次执行不产生重复任务

### Requirement: 明确选择用备份版本替换已有任务

用户勾选一个当前库中已存在的任务时，界面 MUST 明确提示该项将用备份版本替换当前版本。执行后，该任务 MUST 与备份中的版本一致。未勾选的任务 MUST NOT 受影响。

#### Scenario: 把改乱的任务恢复
- **WHEN** 用户勾选一个已被改乱的已存在任务并确认替换
- **THEN** 该任务恢复为备份中的内容，其他任务不变

### Requirement: 父子任务与依赖内容一并带回

找回一个任务时，系统 MUST 一并带回它在备份中的各级子任务，以及这些任务依赖的标签（当前库中不存在的 MUST 重建，颜色与备份一致）、提醒、桌面便签记录、附件记录和进展记录。未被任何所选任务引用的标签、习惯、打卡记录和附件记录 MUST NOT 被带回。

#### Scenario: 父任务带子任务
- **WHEN** 用户勾选一个在备份中含 3 个子任务的父任务
- **THEN** 执行后 4 个任务都出现，父子关系与备份一致

#### Scenario: 重建依赖的标签
- **WHEN** 所选任务带有一个当前库中已不存在的标签“季度汇报”
- **THEN** 该标签被重建并关联到任务，颜色与备份一致

#### Scenario: 不带回无关内容
- **WHEN** 备份中有一个当前库没有的习惯“晨跑”，但没有所选任务依赖它
- **THEN** 找回后“晨跑”不出现在当前工作区

#### Scenario: 误删任务的附件
- **WHEN** 用户在本机找回一个带附件的误删任务，附件文件仍在磁盘上
- **THEN** 附件记录恢复，附件可以正常打开

### Requirement: 不改动设置、模型配置与同步状态

从备份找回 MUST NOT 改动当前工作区的设置、键盘快捷键、AI 模型连接与默认模型选择、同步状态、已采纳的“我的一天”计划，也 MUST NOT 改动任何 API Key。

#### Scenario: 备份来自配置了其他模型的电脑
- **WHEN** 用户从该备份找回任务
- **THEN** 本机的模型连接、默认模型与验证状态与执行前一致

### Requirement: 显式恢复日／周回顾

找回界面 MUST 提供默认不勾选的“同时恢复日／周回顾”选项。用户勾选时，系统 MUST 恢复备份中的回顾文稿：内容一致的同 ID 文稿跳过，存在内容不同的同 ID 文稿时 MUST 拒绝整次找回。不勾选时，当前工作区的日／周回顾 MUST NOT 被改动。

#### Scenario: 恢复已删除的回顾
- **WHEN** 用户勾选该选项，备份中的某周回顾在当前工作区已不存在
- **THEN** 执行后该周回顾出现，内容与备份一致

#### Scenario: 同一周期存在不同文稿
- **WHEN** 备份与当前工作区对同一周期保存了内容不同的回顾
- **THEN** 整次找回不执行，并提示冲突的周期

#### Scenario: 不勾选
- **WHEN** 用户不勾选该选项执行找回
- **THEN** 当前工作区的日／周回顾与执行前一致

### Requirement: 整次找回原子完成

一次找回中的任务、依赖内容和可选的回顾恢复 MUST 作为一个整体成功或失败；任何一步失败都 MUST NOT 留下部分改动。系统 MUST NOT 提供不经预览、整体并入备份全部缺失内容的导入入口。

#### Scenario: 中途失败
- **WHEN** 执行过程中任何一步失败
- **THEN** 当前工作区与执行前完全一致，界面提示失败原因

#### Scenario: 设置页的入口
- **WHEN** 用户打开“设置 → 数据”
- **THEN** 看到“从备份找回”，没有“导入数据库”；需要查看整库内容时能找到“添加为新工作区”的入口

### Requirement: 找回前的文件校验

系统 MUST 先通过共用文件校验再读取备份内容：比当前应用新的备份 MUST 被拒绝；比当前应用旧的备份 MUST 可以找回，缺失的字段按旧备份兼容。

#### Scenario: 旧版本的备份
- **WHEN** 备份由不含来源标记字段的旧版本生成
- **THEN** 找回的任务正常使用，来源标记按未知处理

#### Scenario: 更新版本的备份
- **WHEN** 备份由比当前应用更新的版本生成
- **THEN** 系统拒绝并提示先升级应用，当前工作区不变
