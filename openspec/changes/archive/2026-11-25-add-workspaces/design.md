## Context

动机见 `proposal.md`。改动之前的现状，以及与方案直接相关的约束：

- 应用启动时固定打开应用数据目录下的 `todo.db`，附件目录是同级的 `attachments/`（`src-tauri/src/lib.rs`）。`AppState` 中的连接和数据目录在启动时确定后不再变化。
- 提醒轮询、外部写入检测、便签窗口的事件回调、托盘与悬浮窗初始化都直接持有这个连接或这个固定路径（`reminders.rs`、`db_watcher.rs`、`note_commands.rs`、`lib.rs`）；另有少量命令不经过访问器直接取连接（`alert_commands.rs`、`reminder_commands.rs`、`widget_commands.rs`）。
- Windows 单实例靠一个命名互斥量实现，第二个实例会显示已有窗口后退出（`lib.rs` 的 `single_instance`）。Tauri 2.11.2 的重启是“先拉起新进程（沿用原参数），再退出旧进程”，新进程会照常经过单实例检测。
- 主窗口的关闭被拦截为隐藏（关闭到托盘）；应用没有拦截退出请求的处理。主窗口原先不保存位置与尺寸，每次启动居中显示 1200×800。
- 番茄钟的会话状态（起点、模式、关联任务）只在前端内存里，配置与历史存在 localStorage（`src/stores/pomodoroStore.ts`）。
- 旧的“导入数据库”（已移除）逐表 `INSERT OR IGNORE`：任务不带来源标记；各表不在同一个事务里；缺失的习惯、打卡记录等会一并并入。
- MCP／CLI 原先在进程启动时确定数据库路径并建立连接。
- AI 连接配置和 `ai_default_model` 存在库内；API Key 存在系统凭证存储，按连接 ID 索引（`ai/credentials.rs`）。
- 仓库接口被设置页、记忆适配器和测试替身引用。界面文案走 i18next，有 zh-CN 和 en-US 两份。
- 规格约束：`task-progress-records` 要求显式恢复具备原子性与冲突保护；`task-period-reviews` 要求已保存回顾支持显式备份恢复；`ai-model-access` 要求导入不覆盖本机模型配置、备份不含 Key 本体。

## Goals / Non-Goals

**Goals:**

- 启动路径是数据的唯一入口：数据库和附件目录只在启动时解析一次，运行期间不变。
- 切换完全复用现有启动流程，不引入运行中替换连接的逻辑，因此不需要改动那批直接持有连接的后台代码。
- 除删除工作区外没有破坏性的文件操作；找回只在本机内容上做加法（用户明确勾选替换的任务除外）。
- 找回可预览、可预期，并且在单个事务内完成。

**Non-Goals:**

- 不重启的切换。
- 备份或添加工作区时携带附件文件。
- 调整同步协议，或在 Android 上提供工作区界面。
- 跨工作区移动或复制任务。
- 把库内偏好拆分成应用级设置。

## Decisions

### D1 清单是应用数据目录下的独立文件

`src-tauri/src/workspace/registry.rs`。`workspaces.json` 保存版本号、激活项 ID，以及每个工作区的 ID、名称、数据目录、创建时间和最近激活时间。

- 数据目录存成相对应用数据目录的相对路径，默认工作区为空串——它的数据目录就是应用数据目录，数据库仍是 `todo.db`、附件仍是 `attachments/`。其他工作区各占 `workspaces/<id>/`，内含 `todo.db` 和 `attachments/`。
- 写入采用“临时文件加原子替换”。
- 清单缺失或无法解析时重建：默认工作区只在它的数据库仍在原位、或磁盘上没有任何工作区（全新安装）时登记，这样被删除过的默认工作区不会在重建时“复活”成一个空库；再扫描 `workspaces/` 下每个含 `todo.db` 的目录，名称回退为目录名。
- 启动时只有“刚重建且清单里只有默认工作区”（全新安装）才允许在数据库缺失时新建。其余情况下一律按“不可用”处理：激活项打不开就按最近使用顺序试其他工作区并提示；全部不可用才报错退出。
- 清单不完整时不会落盘；`load_existing` 供 MCP 使用，只读不建。

备选：把清单放进默认工作区的库——清单必须独立于任何可被替换或被 Agent 写入的工作区，否决。单独建一个 SQLite 索引库——为很小的列表引入第二个库不划算，否决。

### D2 切换 = 更新清单 + 重启

- 激活命令依次：校验目标存在，更新激活项和最近激活时间，保存清单，写入重启标记（应用数据目录下的 `restart.pending`），调用 `AppHandle::request_restart()`。“关闭到托盘”的拦截只针对窗口关闭事件，不会拦住重启。
- 启动流程：新实例发现重启标记时，以短间隔探测单实例锁直到旧实例释放（上限 15 秒）；随后照常经过单实例检测，确认自己是唯一实例后清除标记。等到上限旧实例仍未退出时，新实例按现有第二实例行为退出，标记留给下一次启动。
- 这个等待只在带重启标记时发生，普通的二次启动不会被延迟。

备选：给新进程追加参数——Tauri 的重启沿用原参数，做不到。任何情况下都等待——会让普通的二次启动被无谓延迟，否决。

- **`tauri dev` 下的进程交接**（`workspace/dev_handover.rs`，只在开发构建里生效，仅 Windows）。Tauri 的重启是“拉起新实例后以 0 退出”，`npx tauri dev` 把它当成应用关闭：命令结束、开发服务器停掉，切换后的实例加载不出前端，还留下一个挡住下一次 `tauri dev` 的进程。所以开发构建里被 `tauri dev` 直接启动的进程不初始化应用，只拉起一份真正的应用并等它，充当“锚”；应用实例切换时拉起后继者，把它的进程号写进约定的临时文件，再以约定的退出码结束，锚据此改为等待后继者。cargo 的子进程始终活着，开发会话得以保留，多出来的只有一个不打开数据库、不建窗口的空闲进程。锚退出时应用实例随之退出，不会留下脱离开发会话的进程。验收用的独立构建和发布构建不走这条路径。
- 不重启的切换（运行中更换数据库连接）没有做，留作后续优化，范围和代价见 `README.md` 第 8 节。

### D3 窗口状态与番茄钟会话落在应用级

- 主窗口在配置里改为以隐藏状态创建。启动时先从 `window-state.json` 恢复位置与尺寸，再显示，避免先居中闪一下再跳过去。保存的矩形必须与某个可用显示器有足够重叠才恢复，否则保持默认居中。位置用物理像素，尺寸用逻辑像素。
- 保存：监听主窗口的移动与缩放事件，只记最新值；一个常驻线程每秒检查一次，有变化才写。退出时（包括切换工作区引起的重启）再写一次——为此把 `Builder::run` 换成 `build` 加 `App::run`，以便拿到退出事件。最小化和隐藏时上报的尺寸不保存。
- 番茄钟：会话状态一变就写入 localStorage（运行中每秒一次），内容是会话起点、模式、关联任务、已完成节数、写入时的剩余秒数和时间戳。启动时存在未结束的会话就恢复：运行中的扣掉应用不在的时间，暂停的原样恢复；恢复后仍在运行的会话重新接上计时循环。应用不在期间走到头的会话，由恢复后的第一拍按“走到头”处理。历史记录本就按标题快照写入，不依赖任务仍在当前工作区。

### D4 文件校验与复制

`src-tauri/src/workspace/files.rs`。

- 校验：只读打开，完整性检查，确认必需的表存在，确认结构版本不高于当前。全程不写源文件——不走 `db::connection::open`，因为它会设置 WAL。
- 复制：从只读连接用 SQLite 自带的 `VACUUM INTO` 生成一个一致的单文件副本。当前 rusqlite 只启用了 `bundled`，备份 API 需要额外特性，`VACUUM INTO` 不需要。源文件带着未合并的 `-wal`（例如 MCP 进程仍在使用）时也能得到完整内容，并且不用复制 `-wal` 和 `-shm`。
- 添加工作区：校验、复制到新目录、打开副本执行结构升级。任一步失败都删掉刚建的目录，不留半成品。
- 读取备份（预览和执行）：先在临时目录做一份副本并升级到当前结构，读完即删。旧备份缺字段时直接读会出错，统一走副本最简单。

备选：直接复制 `.db` 及其 sidecar 文件——要自己保证几个文件一致，容易遗漏，否决。

### D5 工作区命令只操作清单和文件

列出、新建、添加、重命名、删除、激活这些命令不触碰当前连接；任务数量等统计用只读连接按需查询。`AppState` 多了一个 `app_data_dir`（应用数据目录），原来的 `data_dir` 现在指当前工作区的数据目录。

### D6 删除：先探测占用，再删条目，最后删文件

- 当前激活的工作区除外（见下）。流程：把数据库文件改名为 `todo.db.deleting` 作为占用探测——Windows 下文件被其他进程打开时改名会失败，此时什么都不改并提示；改名成功后删除才算成立，接着清理凭证、删除清单条目和文件。
- 凭证在探测成功之后才清理：读出这个库里登记的模型连接 ID，减去所有剩余工作区仍在用的，逐个删除。清理失败不阻断删除，只记录。
- 删除当前激活的工作区：它的数据库正被本进程占用，无法原地删除。命令只做登记——给条目打上待删除标记、把激活项换成最近使用的另一个、保存清单——然后重启。新进程启动时先完成登记的删除：探测成功就删条目和文件；仍被别的程序占用就撤掉标记、保留条目，并在启动提示里说明。待删除的条目在界面和切换器里不显示。

备选：先删清单条目再删文件——失败时会留下用户看不见的残留。先删附件目录——数据库文件才是最可能被占用的那一个。

### D7 从备份找回 = 预览 + 单事务执行

`src-tauri/src/db/recovery_repo.rs`。

- 预览：读取备份副本里的全部任务，与当前库按 ID 比对，标出哪些已存在；父任务在前、子任务在后。
- 执行在一个事务里：标签（只带所选任务用到的；本库没有的按备份重建，同名的并入本库的，父标签一并保证存在）→ 任务（整行以备份为准，本机软删除的行恢复为可见；同步元数据保留本机的）→ 标签关联和提醒以备份为准 → 桌面便签的位置与皮肤以备份为准 → 附件记录只补缺 → 进展记录与状态事件 → 可选的回顾文稿。任一步失败整体回滚。
- 进展记录：本机上仍有效的不动；随任务删除而被清空正文的记录按备份恢复，所以找回一个误删的任务时它的历史也一起回来。状态事件只增不改——主键是自增号，不同库之间会撞号，撞上就保留本机的。
- 回顾文稿：同范围不同文稿、同 ID 但本机仍有效且内容不同，都拒绝整次找回；本机已删除的文稿和新文稿用备份版本恢复。这是保留下来的显式选项（R4），默认不勾选。
- 习惯、打卡记录、设置、模型配置、同步状态不在带回范围内。
- 找回完成后记一条导入缺口（同一天只记一条），回顾页据此标明当天含导入的当前任务状态。
- 任务写入后按界面写入的同一条路径登记同步操作。

前端入口替换：仓库接口移除 `importDatabase`，改为 `inspectBackup` 与 `recoverFromBackup`（放在原有的设置仓库里，与备份、导出并列）；记忆适配器、测试替身和设置页同步更新。

### D8 MCP／CLI 的目标解析

`src-tauri/src/mcp/target.rs`。

- `--profile` 是全局参数，与 `--db-path` 互斥（由命令行参数层保证）。
- 解析次序：`--db-path`、`--profile`、跟随激活项。没有清单时跟随激活项等于现有的默认路径，旧配置无需修改。
- 跟随激活项：服务进程每次工具调用前重新读清单；目标变了就关闭旧连接、打开新工作区。常驻的 MCP 进程因此在用户切换后写入新的激活工作区，并且不再占用旧工作区的文件。
- 名称匹配去除首尾空白且不区分大小写；找不到时报错并列出可用名称。

### D9 新建空白工作区时的偏好复制

复制白名单内的 `settings` 键：语言、键盘快捷键、快捷键开关、悬浮窗位置与尺寸、气泡配色、番茄钟窗口位置、便签默认样式、系统通知开关。`ai_default_model` 和任何引用工作区内数据的键不在白名单内。

### D10 Android 不参与

移动端构建不读取清单，继续使用现有的单一数据库路径，不出现工作区入口（前端的切换器只在桌面平台显示）。

### D11 附件缺失的呈现

取附件文件路径的命令在文件不在磁盘上时返回空值，附件缩略图据此显示“文件缺失”占位，不呈现为可打开的附件，但仍可删除这条记录。图片加载失败也按缺失处理。

## Risks / Trade-offs

- [切换要重启：窗口消失再出现，未保存的输入会丢] → 这是已确认的取舍；用窗口状态恢复和番茄钟持久化把可感知的损失压到只剩未保存的输入。实际使用中切换频繁的话，再评估不重启的方案（后端换连接加前端整页重载）。
- [重启与单实例检测存在竞态，处理不当会导致切换后应用不再出现] → 重启标记、有上限的等待、超时回退；端到端测试覆盖连续的启动路径。
- [`tauri dev` 下的重启行为可能与发布版不同，项目里也记录过开发模式的孤儿进程问题] → 见 `README.md` 的验收记录。
- [清单损坏或被手工编辑] → 启动时校验并重建，永不删除数据；名称丢失时回退为目录名。
- [从文件添加的工作区没有附件文件] → 明确的“文件缺失”状态；带附件的工作区包留待后续。
- [找回替换已有任务后，任务需要被后续的同步视为本机变更] → 走与界面写入相同的同步登记。同步引擎目前只在测试中被调用，实施时以现有同步契约的测试为准。
- [“导入数据库”入口消失是行为变化] → 发布说明写明替代路径；预览默认勾选缺失任务，让最常见的“找回误删任务”一步完成。
- [删除工作区不可恢复] → 确认框显示名称和任务数；占用探测保证失败不半完成；管理界面提供删除前的备份入口（设置页的“备份数据库”）。
- [偏好跟工作区走，换工作区后语言或快捷键可能不同] → 新建空白工作区时复制偏好；从文件添加的工作区以文件内的为准。
- [日／周回顾的显式恢复最初不在方案里] → 已作为 R4 审核确认保留；它只影响找回界面的一个选项和 `task-progress-records` 的一处措辞。

## Migration Plan

- 部署：首次启动自动登记“默认工作区”，不移动文件；清单和窗口状态文件缺失时自动创建。没有数据库结构迁移。
- 回滚：旧版本应用仍然打开默认位置的数据库，不受清单和新工作区目录影响；删除清单文件即可让新版本按首次启动重建。新工作区目录对旧版本不可见，数据不受影响。
- 发布说明写明三处行为变化：“导入数据库”入口的变化、切换会重启应用、主窗口恢复上次的位置与尺寸。

## Open Questions

- 重启等待上限先取 15 秒，按实测调整。
- 侧边栏折叠时工作区名称目前用小字换行显示（过长时截断并以悬浮提示补全），观感可在日常使用中再调。
