## Why

TodoFlow 桌面应用固定只打开一个数据库，而 MCP／CLI 可以用 `--db-path` 写入任意文件：Agent 写进另一个库的任务在应用里看不到；应用内唯一的“导入数据库”又是盲目整体合并，用户无法先看清备份里有什么再决定。引入“工作区”（同一时间只激活一个的独立数据空间）和“先预览、再勾选”的从备份找回，可以让用户和 Agent 把不同用途的数据分开、随时查看任一备份，并且除明确确认的删除外不破坏任何现有内容。

四项选择已由用户审核确认（2026-11-24，审批通过）：切换时重启应用、第一版只对当前工作区提醒、偏好设置跟工作区走，以及“从备份找回”保留“同时恢复日／周回顾”选项。审核记录见同目录 `README.md`。

## What Changes

- 引入工作区：一个工作区是一个数据库文件加它的附件目录；清单保存在所有库之外；同一时间只激活一个，至少保留一个，名称唯一。升级后现有数据原地登记为“默认工作区”，不移动文件。
- 工作区管理：新建空白、从文件添加（复制，不引用原路径）、重命名、删除、管理界面与侧边栏切换器；“备份到文件”保留，作用于当前工作区。
- 切换通过重启应用完成。重启必须可靠：新实例等待旧实例退出；主窗口位置与尺寸、进行中的番茄钟计时在重启后保持。
- **BREAKING**：“导入数据库”由“从备份找回”取代。先预览再勾选，默认只找回当前库中没有的任务，已存在的不动；带回范围限于所选任务及其依赖内容；整次执行原子完成。不再提供不经预览、整体并入备份全部缺失内容的入口，需要整库内容时添加为新工作区。
- “添加工作区”与“从备份找回”共用一套文件校验，不通过则拒绝，现有数据零改动。
- MCP／CLI 新增 `--profile <名称>` 指定工作区；不指定时跟随当前激活的工作区，每次调用重新确定。
- 由模型直接决定的规则：提醒只对当前工作区生效；偏好设置跟工作区走；从文件添加的工作区里附件显示“文件缺失”；删除工作区时清理只有它在用的 API Key。
- 第一版不做：无感热切换、整库覆盖、所有工作区都提醒、任务跨工作区移动或复制、带附件的工作区包、把应用级设置从库里拆出。

## Capabilities

### New Capabilities

- `workspaces`：工作区的数据归属、清单与唯一激活、升级登记、新建、从文件添加、重命名、删除、凭证清理、管理界面、文件校验，以及提醒、偏好和附件的归属规则。
- `workspace-switching`：通过重启切换工作区、单实例等待、主窗口位置与番茄钟计时跨重启保持、激活工作区不可用时的回退。
- `backup-recovery`：从备份文件先预览再勾选地找回任务，默认只找回缺失任务，原子执行，不改动设置与模型配置，可显式恢复日／周回顾。
- `agent-workspace-targeting`：MCP 服务与命令行如何确定目标工作区（跟随激活项或 `--profile` 指定），以及与 `--db-path` 的关系。

### Modified Capabilities

- `task-progress-records`：“本机保存与可恢复的数据生命周期”中备份找回的语义改为——所选任务缺失的进展记录与真实事件随任务带回且只增不改；显式恢复选项的范围收窄为日／周回顾。

`task-period-reviews` 要求已保存回顾支持显式备份恢复，`ai-model-access` 要求导入不得覆盖本机模型配置，两者的要求保持不变，由 `backup-recovery` 继续满足。

## Impact

- Rust／启动：应用启动时从清单解析数据库路径与附件目录；单实例检测增加重启等待；新增工作区清单模块与命令、主窗口状态与番茄钟会话的持久化；Android 沿用现有单一数据库路径。
- Rust／数据：新增“从备份找回”的预览与执行命令（单事务），替换现有 `import_database`；共用文件校验；新增工作区的目录布局。既有数据不迁移、不移动。
- MCP／CLI：参数解析新增 `--profile`，目标解析改为经清单，并在每次工具调用时重新确定。
- 前端：侧边栏切换器、工作区管理对话框、找回对话框、设置页“数据”区；番茄钟会话持久化；附件缺失占位；界面文案需同时提供中英文。
- 行为变化：主窗口在启动时恢复上次的位置与尺寸（原先固定居中）；“导入数据库”入口消失；切换工作区会重启应用。
- 文档：README、WIKI、CLAUDE.md。
- 审核入口：同目录 `README.md`。行为要求见 `specs/`，取舍与数据语义见 `design.md`，实施顺序见 `tasks.md`。
